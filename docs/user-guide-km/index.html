១.១ តើ VarmanWAF ជាអ្វី?

VarmanWAF គឺជា វេទិកាការពារគេហទំព័រ (Web Application Firewall) ដែលអ្នកអាចដំណើរការដោយខ្លួនឯង (self-hosted)។ វាដាក់នៅពីមុខគេហទំព័រ ឬ API របស់អ្នក ដើម្បីពិនិត្យរាល់សំណើ (request) ដែលចូលមក — ប្រសិនបើសំណើនោះជាការវាយប្រហារ (SQL Injection, XSS, ការស្កេនរកចន្លោះប្រហោង ។ល។) វានឹងទប់ស្កាត់ ឬកត់ត្រាទុកមុនពេលទៅដល់ម៉ាស៊ីនមេពិតរបស់អ្នក។

ប្រព័ន្ធមានពីរផ្នែកធំៗ៖

  • Control Plane (ផ្ទាំងគ្រប់គ្រងមជ្ឈមណ្ឌល) — ផ្ទាំងបញ្ជា និង REST API នៅច្រក 9080 ព្រមទាំង gRPC នៅច្រក 9090។ វាជាកន្លែងដែលអ្នកកំណត់អ្វីៗទាំងអស់ និងរក្សាទុកទិន្នន័យក្នុង PostgreSQL។
  • Edge Agent (ភ្នាក់ងារនៅគែមបណ្តាញ) — ដំណើរការនៅជិតគេហទំព័រ ដោយប្រើ Pingora ជាម៉ាស៊ីនបញ្ជូនសំណើ។ វាទទួលច្បាប់ពី Control Plane ហើយអនុវត្តភ្លាមៗ។
ចំណុចសំខាន់ Control Plane មិនស្ថិតនៅក្នុងផ្លូវនៃសំណើទេ។ បើវាបិទ ឬដាច់ គេហទំព័រនៅតែដំណើរការធម្មតា ព្រោះ Edge Agent រក្សាច្បាប់ចុងក្រោយទុកក្នុងម៉ាស៊ីនខ្លួនឯង។

១.៤ របៀបដំណើរការសុវត្ថិភាព (សង្ខេប)

រាល់សំណើមួយឆ្លងកាត់ដំណាក់កាលទាំងនេះនៅ Edge៖

  1. Canonicalization — ធ្វើឱ្យ URL និងទិន្នន័យមានទម្រង់តែមួយ (decode មានដែនកំណត់ បង្រួម path) ដើម្បីកុំឱ្យ /open/../admin បោកបញ្ឆោតប្រព័ន្ធបាន។
  2. Signature Lane — ស្កេនរកលំនាំវាយប្រហារដោយ Aho-Corasick។
  3. Managed Rules (ច្បាប់គ្រប់គ្រង) — ច្បាប់ ១៣ គ្រួសារ (SQLi, XSS, RCE, scanner ។ល។) ផ្តល់ពិន្ទុ anomaly។
  4. Custom Rules (ច្បាប់ផ្ទាល់ខ្លួន) — ច្បាប់ដែលអ្នកសរសេរខ្លួនឯង។
  5. SecLang / CRS — ច្បាប់ OWASP CRS 4.30.0 ដែលបាននាំចូល។
  6. API Schema — ផ្ទៀងផ្ទាត់សំណើ API តាម OpenAPI (បើបើក)។
  7. Rate Limit / Bot / IP / Geo — ដែនកំណត់អត្រា បុត និងបញ្ជី IP/ប្រទេស។

លទ្ធផលចុងក្រោយគឺ Allow (អនុញ្ញាត), Monitor (កត់ត្រាតែប៉ុណ្ណោះ) ឬ Block (ទប់ស្កាត់)។ អ្នកអាចឃើញមូលហេតុនៃការសម្រេចចិត្តទាំងអស់នៅក្នុងទំព័រ Logs និង Reports។

២.២ ការចូលប្រើ (Login)

  1. បើក browser ទៅ https://localhost:9080។
  2. បញ្ចូលអ៊ីមែល និងពាក្យសម្ងាត់ រួចចុច Sign in។
  3. ប្រសិនបើអ្នកបានចុះឈ្មោះ Passkey (WebAuthn) អ្នកអាចចុចប៊ូតុងចូលដោយ Passkey ជំនួសវិញបាន។
ការការពារការសាកល្បងពាក្យសម្ងាត់ ប្រព័ន្ធអនុញ្ញាតឱ្យព្យាយាមចូលបានតែ ១០ ដងក្នុង ១ នាទី ក្នុងមួយ IP។ បើលើស វានឹងឆ្លើយតបជាមួយលេខកូដ 429 និងតម្រូវឱ្យរង់ចាំបន្តិច។ នេះជាមុខងារការពារធម្មតា។

២.៣ ជំហានដំបូងបន្ទាប់ពីចូល

  1. បង្កើតគេហទំព័រ (Site) — ទៅ Sites → Add site បំពេញឈ្មោះ និងដែន (domain)។
  2. កំណត់ Origin — បញ្ចូលអាសយដ្ឋានម៉ាស៊ីនមេពិតរបស់អ្នក (ឧ. http://10.0.0.5:8080)។
  3. ពិនិត្យសុវត្ថិភាព — ទៅ Protection ដើម្បីមើលថា Engine ដំណើរការលើរបៀបណា (Varman / Legacy / Shadow)។
  4. ភ្ជាប់ចរាចរណ៍ — បង្វែរ DNS នៃដែនរបស់អ្នកមកកាន់ម៉ាស៊ីនដែលដំណើរការ VarmanWAF។
  5. តាមដានលទ្ធផល — ទៅ Logs និង Dashboard ដើម្បីមើលចរាចរណ៍ និងការទប់ស្កាត់។

ជំពូកទី ៣ — ផ្ទាំងគ្រប់គ្រង (Dashboard)

៣.១ ទិដ្ឋភាពទូទៅ

Dashboard គឺជាផ្ទាំងសង្ខេបដំបូងដែលអ្នកឃើញបន្ទាប់ពីចូល។ វាបង្ហាញ៖

  • ស្ថានភាពបណ្តាញ (Fleet) — ភ្នាក់ងារ (agent) ប៉ុន្មានកំពុងដំណើរការ / បិទ។
  • សង្ខេបចរាចរណ៍ — ចំនួនសំណើ ការទប់ស្កាត់ និងការតាមដានក្នុងរយៈពេលដែលបានជ្រើស។
  • ផែនទីពិភពលោក — ប្រភពនៃចរាចរណ៍តាមប្រទេស។
  • ក្បួនពិនិត្យគ្របដណ្តប់ (Coverage) — តើគេហទំព័រណាមួយកំពុងត្រូវបានការពារ និងច្បាប់ណាកំពុងសកម្ម។
ចំណាំ Dashboard គឺជាផ្ទាំង សង្ខេបតែប៉ុណ្ណោះ។ បើអ្នកចង់បានរបាយការណ៍ពេញលេញ (ឧ. សម្រាប់ផ្ញើទៅថ្នាក់គ្រប់គ្រង) សូមបង្កើតវានៅទំព័រ Reports ដែលអាចទាញយកបានជាឯកសារ HTML។

៣.២ របៀបប្រើប្រាស់

  1. ជ្រើសរយៈពេល (window) នៅជ្រុងខាងលើ ដើម្បីមើលស្ថិតិតាមកាលកំណត់ផ្សេងៗ។
  2. ចុចលើចំនួនណាមួយ (ឧ. ការទប់ស្កាត់) ដើម្បីលោតទៅកំណត់ហេតុដែលពាក់ព័ន្ធ។
  3. បើឃើញភ្នាក់ងារណាមួយពណ៌ក្រហម សូមពិនិត្យទំព័រ Agents និងការតភ្ជាប់បណ្តាញ។

៤.១ បញ្ជីគេហទំព័រ

ទំព័រ Sites បង្ហាញគេហទំព័រទាំងអស់ដែលអ្នកកំពុងការពារ។ សម្រាប់គេហទំព័រនីមួយៗ អ្នកនឹងឃើញ៖

  • ឈ្មោះ និងដែន (Domains) — ដែនដែលចរាចរណ៍ត្រូវបានបញ្ជូនមកគេហទំព័រនេះ។
  • របៀប Engine — varman (ម៉ាស៊ីនថ្មី កំពុងអនុវត្ត), legacy (ម៉ាស៊ីនចាស់) ឬ shadow (ដំណើរការទាំងពីរ ដើម្បីប្រៀបធៀបលទ្ធផល)។
  • ស្ថានភាព — សកម្ម ឬផ្អាក។
  • ស្ថិតិរហ័ស — ចំនួនសំណើ និងការទប់ស្កាត់ថ្មីៗ។

ការបង្កើតគេហទំព័រថ្មី

  1. ចុចប៊ូតុង Add site (បន្ថែមគេហទំព័រ)។
  2. បំពេញ ឈ្មោះ (ឧ. «គេហទំព័រក្រុមហ៊ុន») និង ដែន (ឧ. www.example.com)។ អ្នកអាចបន្ថែមដែនច្រើនបាន។
  3. ចុច Save។ គេហទំព័រថ្មីនឹងបង្ហាញក្នុងបញ្ជី។
  4. ចូលទៅក្នុងគេហទំព័រ ដើម្បីកំណត់ Origin (ម៉ាស៊ីនមេពិត) នៅជំពូក ៤.៣។
ចំណាំ នៅពេលបង្កើតគេហទំព័រថ្មី ប្រសិនបើអ្នកប្រើរបៀប all-in-one (ទាំងអស់ក្នុង container តែមួយ) សូម restart container ម្តង ដើម្បីឱ្យ agent ចុះឈ្មោះជាមួយគេហទំព័រថ្មី។

៤.២ បន្ទប់ធ្វើការរបស់គេហទំព័រ (Site workspace)

នៅពេលចុចលើគេហទំព័រណាមួយ អ្នកនឹងឃើញផ្ទាំងរងជាច្រើននៅខាងឆ្វេង ដែលបែងចែកជា៖

៤.៣ Origin — ម៉ាស៊ីនមេពិត (Upstream)

Origin គឺជាកន្លែងដែលចរាចរណ៍សុវត្ថិភាពត្រូវបញ្ជូនទៅបន្ទាប់ពីឆ្លងកាត់ការពិនិត្យ។ វាអាចជាម៉ាស៊ីនមេតែមួយ ឬជាក្រុមម៉ាស៊ីនច្រើន (pool) ដែលចែកចាយបន្ទុក។

អ្វីដែលអ្នកអាចកំណត់បាន

  • អាសយដ្ឋាន — ឧ. http://10.0.0.5:8080 ឬ https://backend.internal។
  • TLS ទៅ Origin — បើម៉ាស៊ីនមេពិតប្រើ HTTPS។
  • SNI / Host header — ឈ្មោះដែនដែលត្រូវផ្ញើទៅ origin បើខុសពីដែនអ្នកប្រើ។
  • Health check — ផ្លូវសម្រាប់ពិនិត្យសុខភាពម៉ាស៊ីនមេ។
  • Failover — អ្វីដែលត្រូវធ្វើបើ pool ធ្លាក់៖ ប្តូរទៅ pool បម្រុង ឬឆ្លើយតបស្តង់ដារ។

ជំហានកំណត់ Origin

  1. ចូលគេហទំព័រ → ផ្ទាំង Origin។
  2. ចុច Add upstream បំពេញអាសយដ្ឋានម៉ាស៊ីនមេពិត និងទម្ងន់ (weight) បើមានច្រើន។
  3. កំណត់ TLS/SNI បើចាំបាច់។
  4. ចុច Save — ការផ្លាស់ប្តូរនឹងត្រូវបញ្ជូនទៅ Edge ភ្លាមៗ។

៤.៤ ការកំណត់គេហទំព័រ (Site settings)

  • ឈ្មោះ និងដែន — កែសម្រួលព័ត៌មានមូលដ្ឋាន។
  • Engine mode — ជ្រើសរវាង varman, legacy ឬ shadow។ ការផ្លាស់ប្តូរត្រូវបានបញ្ជូនទៅ Edge ភ្លាមៗ។
  • Advanced mode និង Custom layers — បើក/បិទស្រទាប់សុវត្ថិភាពកម្រិតខ្ពស់។
  • Monitor lists — បញ្ជីដែលគ្រាន់តែតាមដាន (មិនទប់ស្កាត់)។
  • Log options — ជម្រើសកត់ត្រា។

៤.៥ Caching — ឃ្លាំងសម្ងាត់

ឃ្លាំងសម្ងាត់ជួយឱ្យគេហទំព័រលឿនជាងមុន ដោយរក្សាទុកចម្លើយមួយចំនួននៅ Edge ដើម្បីមិនចាំបាច់ទៅដល់ម៉ាស៊ីនមេពិតរាល់ដង។

  1. ចុច Add rule ដើម្បីបង្កើតច្បាប់ cache (តាម path ឬប្រភេទឯកសារ ឧ. *.css, /images/*)។
  2. កំណត់ TTL (រយៈពេលរក្សាទុក) និងកូនសោ (key) បើចាំបាច់។
  3. អាច Purge (សម្អាត) តាម path ឬ tag នៅពេលអ្នកធ្វើបច្ចុប្បន្នភាពខ្លឹមសារ។
ចំណាំ ប្រព័ន្ធ មិនដែល cache ចម្លើយដែលត្រូវបានទប់ស្កាត់ ឬចម្លើយផ្ទាល់ខ្លួន (personalised) ឡើយ។

៤.៦ SSL — វិញ្ញាបនបត្រ

  1. វិធីទី ១ — ACME ស្វ័យប្រវត្តិ៖ ចុច Issue certificate ជ្រើស Let's Encrypt និងវិធីផ្ទៀងផ្ទាត់ (HTTP-01 ឬ DNS-01)។ ប្រព័ន្ធនឹងចេញ និងបន្តអាយុវិញ្ញាបនបត្រដោយស្វ័យប្រវត្តិ។
  2. វិធីទី ២ — បញ្ចូលដោយដៃ៖ បិទភ្ជាប់ certificate និង private key (ទម្រង់ PEM)។
  3. ពិនិត្យ កាលបរិច្ឆេទផុតកំណត់ — ប្រព័ន្ធព្រមានជាមុន។

៤.៧ Traffic — ស្ថិតិចរាចរណ៍

  • ចំនួនសំណើ និងប្រភេទលេខកូដ (2xx, 3xx, 4xx, 5xx)។
  • បរិមាណទិន្នន័យ (bandwidth) និងផ្លូវដែលគេចូលច្រើនបំផុត (top paths)។
  • អត្រា cache hit និងប្រទេសដើមនៃចរាចរណ៍។

ជ្រើសរយៈពេលខាងលើ ដើម្បីប្តូរទិដ្ឋភាព (ម៉ោង, ថ្ងៃ, សប្តាហ៍)។ កាលបរិច្ឆេទប្រើ តំបន់ពេលវេលាដែលបានកំណត់ក្នុង Settings → Display។

៤.៨ Rewrite — ការបង្វែរ និងកែ URL

  1. ចុច Add rule។ ជ្រើសប្រភេទ៖ Route (បញ្ជូនទៅ upstream ផ្សេង / redirect / ឆ្លើយតបស្តង់ដារ) ឬ Rewrite (ជំនួស URL)។
  2. កំណត់លក្ខខណ្ឌ (host/path) និងសកម្មភាព។
  3. ប្រើ Preview ដើម្បីសាកល្បងជាមួយ URL គំរូ មុនពេលរក្សាទុក។
  4. ច្បាប់ត្រូវបានអនុវត្តតាមលំដាប់ពីលើចុះក្រោម។

ជំពូកទី ៥ — ការការពារ (Protection)

៥.១ ទិដ្ឋភាពទូទៅនៃផ្ទាំងការពារ

នេះគឺជាផ្ទាំងសំខាន់បំផុតនៅក្នុងប្រព័ន្ធ។ វាបង្រួមអ្វីៗពាក់ព័ន្ធសុវត្ថិភាពទាំងអស់របស់គេហទំព័រទៅជាផ្ទាំងតែមួយ ដែលមានផ្ទាំងរង ៤៖

តំណចាស់ៗនៅតែប្រើបាន តំណចាស់ដូចជា /security/waf ឬ /security/cc នឹងបញ្ជូនអ្នកទៅផ្ទាំងរងដែលត្រូវគ្នាដោយស្វ័យប្រវត្តិ។

៥.២ Rules — ច្បាប់សុវត្ថិភាព

ច្បាប់គ្រប់គ្រង (Managed rules)

ប្រព័ន្ធមានច្បាប់គ្រប់គ្រង ១៣ គ្រួសារ (VARMAN-1001..1061) ដែលរាយការវាយប្រហារទូទៅ៖ SQL Injection, XSS, RCE (ការប្រតិបត្តិកូដពីចម្ងាយ), path traversal, កម្មវិធីស្កេន, ការស្វែងរកឯកសារសម្ងាត់ (dotfile), វិធីសាស្ត្រ HTTP គ្រោះថ្នាក់, ផ្លូវអ្នកគ្រប់គ្រង, ទំហំ payload ធំលើសកំណត់ ។ល។ ច្បាប់នីមួយៗមាន៖

  • កម្រិតគ្រោះថ្នាក់ (severity) និងពិន្ទុ anomaly។
  • របៀប (mode)៖ off (បិទ), monitor (តាមដានតែប៉ុណ្ណោះ), block (ទប់ស្កាត់)។
  1. រកច្បាប់ដែលចង់កែ តាមការស្វែងរក ឬតាមគ្រួសារ។
  2. ប្តូរ mode របស់វា។ ការកែតម្រូវនឹងត្រូវកត់ត្រាជា override ហើយមិនបាត់បង់នៅពេលបញ្ជូនច្បាប់ថ្មី។
  3. ចង់ដឹងថាច្បាប់នេះបាញ់លើសំណើបែបណា? សាកល្បងនៅ Rule tester (ជំហានខាងក្រោម)។

ច្បាប់ផ្ទាល់ខ្លួន (Custom rules)

អ្នកអាចសរសេរច្បាប់ផ្ទាល់ខ្លួនជាភាសាសាមញ្ញ ដូចជា៖

http.request.uri.query contains "union select"
cf.waf.score.sqli ge 30
http.request.uri.path eq "/secret-admin"
  1. ចុច Add rule ក្នុងផ្នែក Custom rules។
  2. បំពេញ ឈ្មោះ, កន្សោម (expression), និង សកម្មភាព (block ឬ log) ព្រមទាំងពិន្ទុបើចាំបាច់។
  3. ប្រើ Rule tester ដើម្បីសាកល្បងកន្សោមលើសំណើគំរូ — វានឹងបង្ហាញថាតើលក្ខខណ្ឌណាត្រូវ។
  4. រក្សាទុក។ ច្បាប់ត្រូវបានបញ្ជូនទៅ Edge ភ្លាមៗ។

៥.៣ CC — ការប្រឈមមុខ និង Under attack

  • JS Challenge — បង្ខំឱ្យ browser ដំណើរការកូដ JavaScript ខ្លី ដើម្បីបញ្ជាក់ថាជាមនុស្សពិត។
  • Managed Challenge — ប្រព័ន្ធសម្រេចចិត្តខ្លួនឯងថាតើគួរប្រឈមមុខ ឬអនុញ្ញាត។
  • Under attack mode — បង្កើនកម្រិតការពារ និងពង្រឹងការត្រួតពិនិត្យ នៅពេលគេហទំព័រកំពុងត្រូវបានវាយប្រហារដោយចរាចរណ៍ច្រើន។

រាល់ការសម្រេចចិត្តត្រូវបានកត់ត្រាជាព្រឹត្តិការណ៍ ជាមួយមូលហេតុ ដែលអាចមើលបាននៅ Logs។

៥.៤ Policy tuning — ការលៃតម្រូវគោលនយោបាយ

នេះជាផ្នែកដែលមានអំណាចបំផុត។ វាមានផ្នែករងជាច្រើននៅផ្នែកខាងស្តាំ (rail) ដូចខាងក្រោម។

៥.៤.១ សង្ខេបគោលនយោបាយ (Policy summary)

បង្ហាញជា chip សម្រាប់ស្រទាប់ (layer) នីមួយៗ ដើម្បីឱ្យអ្នកឃើញភ្លាមថាអ្វីកំពុងសកម្ម និងអ្វីកំពុងបិទ។

៥.៤.២ ស្ថានភាពគេហទំព័រ (Site posture)

នៅទីនេះអ្នកកំណត់អ្វីដែលគេហទំព័រនេះដំណើរការ៖ engine mode, advanced mode, ស្រទាប់ផ្ទាល់ខ្លួន (custom layers) និង បញ្ជីតាមដាន (monitor lists)។

៥.៤.៣ ស្ថានភាពអនុវត្តជាក់ស្តែង (Effective posture)

នេះជាផ្នែកសំខាន់សម្រាប់ភាពស្មោះត្រង់៖ វាបង្ហាញ លទ្ធផលចុងក្រោយ បន្ទាប់ពីបញ្ចូលគោលនយោបាយ (policy) ជាមួយការកំណត់ក្នុងគេហទំព័រ។ នៅពេលស្រទាប់ពីរនិយាយផ្ទុយគ្នា ស្រទាប់ដែលតឹងរ៉ឹងជាងឈ្នះ។ ដូច្នេះ «បានបោះផ្សាយ» មិនដូចគ្នានឹង «បានអនុវត្ត» — ហើយផ្ទាំងនេះបង្ហាញភាពខុសគ្នានោះឱ្យអ្នកឃើញផ្ទាល់ភ្នែក។

៥.៤.៤ ការលើកលែងច្បាប់ (Rule exceptions)

អ្នកអាចលៃតម្រូវច្បាប់ជាក់លាក់ដោយមិនបិទវាទាំងស្រុង៖

  • Disable — បិទច្បាប់ទាំងស្រុង។
  • Monitor only — កត់ត្រាតែប៉ុណ្ណោះ មិនទប់ស្កាត់។
  • Score adjustment — បន្ថយ/បង្កើនពិន្ទុ anomaly របស់ច្បាប់។
  • Target exclusions — លើកលែងតែផ្នែកជាក់លាក់នៃសំណើ (ឧ. parameter q ក្នុង query string) ដោយអាចកំណត់ទីតាំងតាម path និងឈ្មោះ target ដូចជា query:q, body:content, cookie:x, header:x។
ចំណាំបច្ចេកទេស ច្បាប់គ្រប់គ្រងដែលប្រើពិន្ទុ cf.waf.score.* មិនអាចលើកលែងតាម target បានទេ (ដំណាក់កាលទី ១ នៃ pipeline)។ ផ្ទាំងនឹងប្រាប់អ្នកផ្ទាល់ ជំនួសឱ្យការបង្ហាញថាបានសម្រេច ដោយប្រកាសមិនពិត។

៥.៤.៥ កញ្ចប់លើកលែង (Exclusion packages)

កញ្ចប់លើកលែងមានពីរប្រភេទ៖

  1. entries — កញ្ចប់សម្រាប់កម្មវិធីពេញនិយម (WordPress, Next.js, Nextcloud WebDAV, កម្មវិធីកែអត្ថបទ rich-text ។ល។)។ ធាតុនីមួយៗភ្ជាប់តាម path និងអាចកំណត់ target ជាក់លាក់ (ឧ. query:q) សម្រាប់ទាំងច្បាប់គ្រប់គ្រង និងច្បាប់ផ្ទាល់ខ្លួន។
  2. seclang — នាំចូលឯកសារ SecLang ពីខាងក្រៅ (ឧ. plugin លើកលែងរបស់ OWASP CRS)។ ប្រព័ន្ធនឹងទាញយក ពិនិត្យថាអានបាន រក្សាទុក ជាមួយរបាយការណ៍នៃអ្វីដែលវាមាន (ចំនួនតាមប្រភេទ directive — មិនមែនការប្រឌិត) ហើយចងក្រងចូលក្នុង virtual patches របស់គេហទំព័រ។
  1. ជ្រើសកញ្ចប់ដែលចង់ប្រើ (ឧ. WordPress)។
  2. ភ្ជាប់វាទៅ path prefix (ឧ. / ឬ /blog)។
  3. ពិនិត្យ របាយការណ៍នាំចូល (ចំនួនធាតុ) មុនពេលអនុវត្ត។
  4. ចុច Preview and apply ដើម្បីអនុវត្ត។

៥.៤.៦ មើលជាមុន និងអនុវត្ត (Preview and apply)

មុនពេលអនុវត្ត ប្រព័ន្ធចងក្រង (compile) កញ្ចប់ថ្មី និងបង្ហាញ ភាពខុសគ្នា (diff) — ដូច្នេះអ្នកដឹងច្បាស់ថាអ្វីនឹងផ្លាស់ប្តូរ។ បន្ទាប់មកចុច Apply ដើម្បីបញ្ជូនទៅ Edge។

៥.៤.៧ ប្រវត្តិកំណែ (Version history)

រាល់ការផ្លាស់ប្តូរត្រូវបានចុះកំណែ។ អ្នកអាចមើលកំណែចាស់ និង ត្រឡប់ក្រោយ ទៅកំណែណាមួយបានយ៉ាងងាយ។

៥.៥ Rate limiting — ដែនកំណត់អត្រា

ការពារការប្រើប្រាស់លើសកម្រិត (ឧ. brute force ឬ scraping) ដោយកំណត់ចំនួនសំណើអនុញ្ញាតក្នុងមួយរយៈពេល៖

  1. ចុច Add limiter។
  2. ជ្រើស កូនសោ (key)៖ តាម IP, តាម header, តាម cookie ឬតាម path។
  3. កំណត់ window (ឧ. 60 វិនាទី) និង ចំនួនអនុញ្ញាត (ឧ. 100) ព្រមទាំង burst បើចង់។
  4. ជ្រើសសកម្មភាព៖ តាមដាន ឬទប់ស្កាត់ (ឆ្លើយតប 429)។
  5. ភ្ជាប់ limiter ទៅផ្លូវជាក់លាក់ ឬទាំងគេហទំព័រ។

៥.៦ Bot protection — ការគ្រប់គ្រងបុត

  • Bot posture — ជ្រើសរបៀប៖ off, monitor, challenge ឬ block។
  • Verified bots — បញ្ជីបុតល្បីៗ (ឧ. Googlebot) ដែលត្រូវបានផ្ទៀងផ្ទាត់ដោយ reverse DNS ដើម្បីមិនទប់ស្កាត់ខុស។
  • Heuristics — ការវិភាគ user-agent និងសញ្ញាប្រូបាប៊ីលីតេផ្សេងៗ ដែលច្រោះទៅ CC។

ជំពូកទី ៦ — ការគ្រប់គ្រងការចូលប្រើ (Access control)

៦.១ ច្បាប់ IP (IP rules)

ច្បាប់ IP ត្រូវបានពិនិត្យ មុន pipeline សុវត្ថិភាព។ វាអាចជា៖

  • Allow list — អនុញ្ញាតតែ IP/CIDR ក្នុងបញ្ជី។
  • Deny list — ទប់ស្កាត់ IP/CIDR ក្នុងបញ្ជី។
  • IP Groups — យោងទៅក្រុម IP ដែលបានកំណត់រួច (ជំពូក ១៣) ដើម្បីប្រើឡើងវិញបានច្រើនគេហទំព័រ។
  1. ចុច Add rule។
  2. បំពេញ IP ឬ CIDR (ឧ. 203.0.113.0/24) ឬជ្រើស IP Group។
  3. ជ្រើសសកម្មភាព៖ Allow ឬ Deny។
  4. រក្សាទុក — ច្បាប់អនុវត្តភ្លាម។

៦.២ ភូមិសាស្ត្រ និង ASN (Geo policy)

អ្នកអាចអនុញ្ញាត តាមដាន ឬទប់ស្កាត់ចរាចរណ៍តាម ប្រទេស ឬតាម ASN (លេខបណ្តាញរបស់អ្នកផ្តល់សេវា ឧ. Cloudflare = AS13335)។

ប្រភពទិន្នន័យ ទិន្នន័យភូមិសាស្ត្រ និង ASN ទាំងអស់មកពី ipverse តែមួយប៉ុណ្ណោះ៖ ជួរ IP តាមប្រទេសមកពី rir-ip និងជួរ ASN មកពី as-ip-blocks។ ប្រព័ន្ធមិនប្រើប្រភពផ្សេងទេ។
  1. ជ្រើសជួរ (key) ដែលត្រូវការ ឧ. ប្រទេស US ឬ ASN AS13335។
  2. ចុច Sync ដើម្បីទាញយកទិន្នន័យចុងក្រោយពី ipverse ចូល ip_datasets។ ការធ្វើសមកាលកម្ម = ការអនុវត្ត — ជួរដែល synced រួចត្រូវបានបញ្ជូនទៅ Edge ភ្លាម។
  3. ជ្រើសសកម្មភាព៖ off / monitor (តាមដាន) / block (ទប់ស្កាត់)។
  4. ពិនិត្យផ្នែក missing_keys — បើជួរណាមិនទាន់ synced វានឹងបង្ហាញច្បាស់ថា មិនត្រូវបានអនុវត្ត។ ប្រព័ន្ធមិនបង្ហាញថាសកម្ម បើវាមិនពិតទេ។

៦.៣ ការវិភាគ IP អ្នកប្រើ (Client IP analysis)

ឧបករណ៍នេះជួយឆ្លើយសំណួរថា៖ «បើ IP នេះចូលមក តើ Edge នឹងសម្រេចចិត្តយ៉ាងណា?»។

  1. បិទភ្ជាប់ IP ដែលចង់វិភាគ។
  2. ប្រព័ន្ធប្រើ loader ដូចគ្នាបេះបិទ នឹង Edge ដើម្បីពិនិត្យ៖ តើ IP នេះចូលក្នុងជួរប្រទេស/ASN ណា? តើច្បាប់ណានឹងបាញ់? តើវាស្ថិតក្នុងបញ្ជីទប់ស្កាត់ឬទេ?
  3. លទ្ធផលបង្ហាញច្បាស់ ដើម្បីឱ្យអ្នកជួសជុលគោលនយោបាយបានត្រឹមត្រូវ។

៦.៤ Basic Auth

អ្នកអាចការពារផ្លូវជាក់លាក់ (ឧ. /staging ឬ /admin) ដោយ username/password បែប HTTP Basic។

  1. ចុច Add credential បំពេញឈ្មោះអ្នកប្រើ និងពាក្យសម្ងាត់។
  2. កំណត់ path ដែលត្រូវការការពារ។
  3. រក្សាទុក។ អ្នកប្រើដែលគ្មានសិទ្ធិនឹងទទួល 401។

ជំពូកទី ៧ — API assets (ការគ្រប់គ្រង API)

៧.១ តើផ្ទាំងនេះធ្វើអ្វី?

សម្រាប់គេហទំព័រដែលមាន API ផ្ទាំងនេះជួយឱ្យអ្នកដឹងថា API ពិតៗកំពុងត្រូវបានហៅបែបណា និងផ្ទៀងផ្ទាត់សំណើទៅតាម OpenAPI document របស់អ្នក។

  • Observed inventory (បញ្ជីសង្កេត) — ចំណុចចូល (endpoint) ដែលឃើញពីចរាចរណ៍ពិត ដោយបំលែងតម្លៃទៅជាទម្រង់៖ /orders/42 → /orders/{id}។
  • Declared spec — ឯកសារ OpenAPI ដែលអ្នកផ្ទុកឡើង។ ផ្ទាំងបង្ហាញភាពខុសគ្នារវាងអ្វីដែលបានប្រកាស និងអ្វីដែលពិតជាកើតឡើង។

៧.២ ការរៀនសូត្រដែលមានដែនកំណត់ (Bounded learning)

ប្រព័ន្ធអាច «រៀន» រចនាសម្ព័ន្ធនៃសំណើ និងចម្លើយពីចរាចរណ៍ពិត — ប៉ុន្តែដោយគោរពគោលការណ៍សំខាន់៖

  • វារៀន រចនាសម្ព័ន្ធ និងចំនួន (ប្រភេទទិន្នន័យ, ឈ្មោះ key, តើ key ណាចាំបាច់តាមសង្កេត) — មិនរៀនតម្លៃ ទេ។
  • ការរៀនធ្វើឡើងតាម ថ្នាក់លេខកូដ (status class) សម្រាប់ចម្លើយ។
  • អាចនាំចេញ សេចក្តីព្រាង OpenAPI — ដោយគ្មានតម្លៃ និងគ្មានបញ្ជាក់ required (ព្រោះវាជាការសង្កេត មិនមែនការប្រកាស)។
  1. ចុច Learn ដើម្បីឱ្យប្រព័ន្ធសង្កេតចរាចរណ៍ក្នុងរយៈពេលខ្លី។
  2. មើល Learned ដើម្បីពិនិត្យលទ្ធផលដែលបានរៀន។
  3. ចុច Export draft ដើម្បីទាញយកសេចក្តីព្រាង OpenAPI។

៧.៣ ការគ្រប់គ្រងតាមប្រតិបត្តិការ (Per-operation controls)

រាល់ operation នៅក្នុង spec មានរបៀបបីជម្រើស៖

របៀបអត្ថន័យ
Offមិនពិនិត្យ operation នេះតាម OpenAPI ទេ
Observeពិនិត្យ និងកត់ត្រាតែប៉ុណ្ណោះ
Enforceពិនិត្យ និងទប់ស្កាត់សំណើដែលមិនត្រឹមត្រូវ
ចំណាំបច្ចេកទេស ការគ្រប់គ្រងនេះគ្រប់គ្រង ស្រទាប់ផ្ទៀងផ្ទាត់ OpenAPI តែប៉ុណ្ណោះ (មិនប៉ះពាល់ engine ដើម)។ ផ្លូវដូច /orders/42 និង /orders/99 ត្រូវបានបង្រួមជា operation តែមួយ (/orders/{id})។ បើ operation ច្រើនត្រូវគ្នា របៀបដែលតឹងរ៉ឹងជាងគេឈ្នះ។ រាល់ការផ្លាស់ប្តូររបៀបត្រូវបានបញ្ជូនទៅ Edge ភ្លាម។

ជំពូកទី ៨ — កំណត់ហេតុ (Logs)

៨.១ ទិដ្ឋភាពទូទៅ

ប្រព័ន្ធមានប្រភេទកំណត់ហេតុពីរ៖

  • Security events (ព្រឹត្តិការណ៍សុវត្ថិភាព) — រាល់សំណើដែល WAF បានសម្រេចចិត្ត (block/monitor) ជាមួយសំណើ canonical, ច្បាប់ដែលបានបាញ់ និងលទ្ធផល។
  • Access log — រាល់សំណើដែល Edge បានឆ្លើយតប។

៨.២ របៀបស្វែងរក

  1. ជ្រើសប្រភេទ (Security ឬ Access)។
  2. ចម្រាញ់តាម៖ គេហទំព័រ, លេខកូដស្ថានភាព, លទ្ធផល (block/monitor), លេខច្បាប់, ផ្លូវ, IP និងរយៈពេល។
  3. ចុចលើជួរណាមួយដើម្បីមើលលម្អិត រួមទាំង «ហេតុអ្វី?» (why resolver) ដែលពន្យល់មូលហេតុនៃការសម្រេចចិត្ត និង body view បង្ហាញខ្លឹមសារដែលបានពិនិត្យ។
ចំណាំសំខាន់ ចម្លើយ 5xx ដែលកើតពីម៉ាស៊ីនមេពិត (pass-through) មិនត្រូវបានកត់ត្រាជា access log ទេ ប៉ុន្តែសំណើដែល WAF ឆ្លើយតបខ្លួនឯង (ឧ. 403) ត្រូវបានកត់ត្រា។

រយៈពេលរក្សាទុកត្រូវបានកំណត់នៅ Settings → Log retention។ ការផ្ញើទៅ Elasticsearch គឺជាជម្រើសបន្ថែម (បិទតាមលំនាំដើម)។

ជំពូកទី ៩ — ការជូនដំណឹង (Alerts & Notifications)

៩.១ ទិដ្ឋភាពទូទៅ

ផ្ទាំងនេះប្រមូលអ្វីៗពាក់ព័ន្ធការជូនដំណឹងទាំងអស់នៅកន្លែងតែមួយ (ធ្លាប់ជាពីរផ្ទាំងដាច់ដោយឡែក)៖

  • Alert rules (ច្បាប់ជូនដំណឹង) — លក្ខខណ្ឌ → កម្រិតសំខាន់ (severity)។
  • Silences (ការបិទស្ងាត់) — ផ្អាកការជូនដំណឹងមួយរយៈ (ឧ. ពេលដឹងរឿងហើយ)។
  • Channels (ឆានែល) — ផ្លូវផ្ញើ៖ អ៊ីមែល (SMTP), Webhook ឬ Telegram។
  • Delivery & History — ប្រវត្តិនៃការផ្ញើ និងលទ្ធផល។
  • Login security — ការព្យាយាមចូលបរាជ័យ និងប្រវត្តិការចូលប្រើ។

៩.២ ការកំណត់ឆានែល

  1. ចូលផ្នែក Channels រួចចុច Add channel។
  2. ជ្រើសប្រភេទ៖
    • Email — បំពេញ SMTP server, ច្រក, username/password, និងអ្នកទទួល។
    • Webhook — បំពេញ URL ដែលនឹងទទួល JSON POST។
    • Telegram — បំពេញ Bot token និង Chat ID។
  3. ចុច Test ដើម្បីផ្ញើសារសាកល្បង។ បើបរាជ័យ ប្រព័ន្ធនឹងប្រាប់ច្បាស់ថាបរាជ័យ — វាមិនបង្ហាញ «ជោគជ័យ» ក្លែងក្លាយទេ។
  4. ភ្ជាប់ឆានែលទៅច្បាប់ជូនដំណឹងដែលពាក់ព័ន្ធ។

៩.៣ Login security

ផ្នែកនេះបង្ហាញការព្យាយាមចូលបរាជ័យ និងប្រវត្តិការចូលប្រើរបស់គណនី។ ប្រើវាដើម្បីរកឃើញការព្យាយាមសាកល្បងពាក្យសម្ងាត់។

ជំពូកទី ១០ — របាយការណ៍ (Reports)

១០.១ ទិដ្ឋភាពទូទៅ

Dashboard ផ្តល់តែសង្ខេប — របាយការណ៍ពេញលេញត្រូវបាន បង្កើត និងទាញយកតាមតម្រូវការ។ របាយការណ៍ជាឯកសារ HTML តែមួយឯកសារ (គ្មាន JavaScript ខាងក្នុង) ដែលអាចផ្ញើ ឬរក្សាទុកបានយ៉ាងងាយ។

១០.២ ការបង្កើតរបាយការណ៍

  1. ជ្រើស គេហទំព័រ (ឬទាំងអស់) និង រយៈពេល (ចាប់ពីថ្ងៃ ដល់ថ្ងៃ — អតិបរមា ៩២ ថ្ងៃ)។
  2. ជ្រើសប្រភេទលទ្ធផលដែលចង់បញ្ចូល (block, monitor ។ល។)។
  3. បើចង់ សរសេរ ចំណងជើង និង footer ផ្ទាល់ខ្លួន (ឧ. ឈ្មោះក្រុមហ៊ុន)។
  4. ចុច Preview ដើម្បីមើលសង្ខេប រួចចុច Generate ដើម្បីទាញយក។
តំបន់ពេលវេលា កាលបរិច្ឆេទ (ថ្ងៃ) និងចំណែកប្រចាំថ្ងៃ (daily buckets) ក្នុងរបាយការណ៍ គោរពតាម តំបន់ពេលវេលាដែលបានកំណត់ក្នុង Settings → Display។

១០.៣ ការផ្ញើតាមកាលវិភាគ (Schedules)

  1. ចូលផ្នែក Schedules រួចចុច Add schedule។
  2. ជ្រើសរយៈពេល៖ ប្រចាំថ្ងៃ / ប្រចាំសប្តាហ៍ / ប្រចាំខែ។
  3. ជ្រើសអ្នកទទួល (អ៊ីមែល) និងគេហទំព័រ។
  4. ប្រើ Send now ដើម្បីសាកល្បងផ្ញើភ្លាមៗ។

ជំពូកទី ១១ — គោលនយោបាយរួម (Policies)

១១.១ តើគោលនយោបាយជាអ្វី?

គោលនយោបាយ (Policy) គឺជាឯកសារដែលមាន ស្រទាប់ (layers) ច្រើន ដូចជា៖ engine posture, CRS tuning, ច្បាប់ផ្ទាល់ខ្លួន, ការលើកលែងច្បាប់, virtual patches, API schema, rate limits, IP access, bot posture និង CRS import។ គេហទំព័រអាច តាម (follow) គោលនយោបាយមួយ ដើម្បីកុំកំណត់ដូចគ្នាម្តងហើយម្តងទៀត។

១១.២ ទំព័រលម្អិតគោលនយោបាយ

  1. ចុចលើគោលនយោបាយណាមួយដើម្បីបើកទំព័រលម្អិត (/policies/:policyId)។
  2. មើល ស្រទាប់នីមួយៗ — ចុច Add layer ដើម្បីបន្ថែមស្រទាប់ថ្មី (ឧ. rate limits ឬ IP access)។
  3. មើល ប្រវត្តិ (history) និង preview នៃលទ្ធផលដែលចងក្រងរួច។
  4. ដើម្បីឱ្យគេហទំព័រប្រើ សូមភ្ជាប់វានៅ Protection → Policy tuning។
ភាពស្មោះត្រង់នៃស្ថានភាព នៅពេលគោលនយោបាយ និងការកំណត់ក្នុងគេហទំព័រនិយាយផ្ទុយគ្នា លទ្ធផលពិតបង្ហាញនៅ Effective posture។ អ្នកអាចទុកចិត្តបានថាអ្វីដែលបង្ហាញជា «សកម្ម» គឺជាអ្វីដែល Edge កំពុងអនុវត្តពិត។

ជំពូកទី ១២ — OWASP CRS

១២.១ ទិដ្ឋភាពទូទៅ

VarmanWAF អាចនាំចូល OWASP Core Rule Set (CRS) ជាច្បាប់បន្ថែម។ កំណែដែលបាននាំចូលបច្ចុប្បន្នគឺ CRS 4.30.0 (ច្បាប់ ៦៩៣)។

  • Categories — មើលច្បាប់តាមប្រភេទ (SQLi, XSS, RCE ។ល។)។
  • Paranoia ceiling — កម្រិត «ភាពប្រុងប្រយ័ត្ន» (១–៤)។ កម្រិតខ្ពស់ = ការពារខ្លាំង ប៉ុន្តែអាចបាញ់ខុសច្រើនជាង។ ចាប់ផ្តើមពីកម្រិតទាប រួចបង្កើនបន្តិចម្តងៗ។
  • Rule catalogue — បញ្ជីច្បាប់ពេញលេញ និងកន្លែងដែលវាសកម្ម។
ការអនុវត្តជាក់ស្តែង ច្បាប់ CRS ដំណើរការជា virtual patches នៅក្នុងគេហទំព័រ។ បើអ្នកចង់លើកលែងច្បាប់ CRS សូមប្រើកញ្ចប់លើកលែងប្រភេទ seclang (ជំពូក ៥.៤.៥)។

ជំពូកទី ១៣ — IP Groups និង Blocked IPs

១៣.១ ក្រុម IP (IP Groups)

ក្រុម IP គឺជាបណ្តុំ IP/CIDR ដែលមានឈ្មោះ អាចយោងពីច្បាប់ IP និង rate limits នៅគ្រប់គេហទំព័រ។

  1. ចុច Add group បំពេញឈ្មោះ (ឧ. «ការិយាល័យ») និងបញ្ជី IP/CIDR។
  2. បន្ថែមធាតុថ្មីៗនៅពេលក្រោយបាន។
  3. នៅពេលកែក្រុម ប្រព័ន្ធបញ្ជូនកញ្ចប់ថ្មីទៅគ្រប់គេហទំព័រដែលយោងវាភ្លាម។

១៣.២ IP ដែលបានទប់ស្កាត់ (Blocked IPs)

នៅពេល WAF ទប់ស្កាត់សំណើពី IP ណាមួយ Edge នឹង បដិសេធសំណើបន្តបន្ទាប់ពី IP នោះរយៈពេល ៦០០ វិនាទី (១០ នាទី) ដោយមិនចាំបាច់ដំណើរការ engine ម្តងទៀត។

  • ប្រភព — ដោយស្វ័យប្រវត្តិ (auto-block) ឬដោយដៃ (manual block)។
  • មូលហេតុ និងវិសាលភាព — តាមគេហទំព័រ ឬទាំងប្រព័ន្ធ។
  • កាលបរិច្ឆេទផុតកំណត់ និងចំនួនប៉ះ។
  1. រក IP ក្នុងបញ្ជី។
  2. ចុច Unblock ដើម្បីដោះវាចេញ (ឧ. ពេលដឹងថាអតិថិជនពិតត្រូវបានបាញ់ខុស)។
  3. អាច Block IP ដោយដៃបានផងដែរ។

ជំពូកទី ១៤ — បណ្តាញ (Fleet)

១៤.១ ភ្នាក់ងារ (Agents)

ភ្នាក់ងារ (agent) គឺជាកម្មវិធីដែលដំណើរការនៅម៉ាស៊ីនរបស់អ្នក (ឬ container) ទទួលច្បាប់ពី Control Plane និងអនុវត្ត។

  • ស្ថានភាព — online / offline ព្រមទាំងពេលវេលាចុងក្រោយដែលឃើញ (heartbeat)។
  • បន្ទុក — ស្ថិតិម៉ាស៊ីន និងកំណែកញ្ចប់ដែលបានទទួល។
  • ការចុះឈ្មោះ — អាចបិទ (registration closed) ដើម្បីកុំឱ្យ agent ប្លែកចូលរួម។ អាចភ្ជាប់អត្តសញ្ញាណដោយ mTLS។

១៤.២ ប្រវត្តិការកំណត់ (Config history)

រាល់ការផ្លាស់ប្តូរដែលបង្កើតកញ្ចប់ថ្មីត្រូវបានចុះកំណែ។ អ្នកអាចមើល៖

  • កំណែនីមួយៗ ជាមួយអ្នកធ្វើ និងពេលវេលា។
  • Diff — អ្វីផ្លាស់ប្តូរពីកំណែមុន។
  • Rollback — ត្រឡប់ទៅកំណែចាស់ ដែលនឹងបញ្ជូនកញ្ចប់នោះទៅ Edge វិញ។

១៤.៣ វដ្តជីវិតគេហទំព័រ (Lifecycle)

ផ្ទាំងនេះជាបញ្ជីត្រួតពិនិត្យ (checklist) បង្ហាញថាគេហទំព័រនីមួយៗស្ថិតក្នុងដំណាក់ណា៖ បង្កើត → កំណត់រួច → ទទួលចរាចរណ៍ → ការពារពេញលេញ និងអ្វីដែលនៅខ្វះនៅដំណាក់នីមួយៗ។

ជំពូកទី ១៥ — ជំនួយការ AI (Assistant)

ជំនួយការ AI ជាជម្រើសបន្ថែម សម្រាប់៖

  • ពន្យល់ព្រឹត្តិការណ៍សុវត្ថិភាព (ហេតុអ្វីបានជាត្រូវទប់ស្កាត់)។
  • ជួយព្រាងច្បាប់ផ្ទាល់ខ្លួន។
ភាពឯកជន ជំនួយការ បិទតាមលំនាំដើម។ គ្មានទិន្នន័យត្រូវបានផ្ញើទៅណាទេ លុះត្រាតែអ្នកកំណត់ provider និង key នៅ Settings → AI assistant។

ជំពូកទី ១៦ — SSL និងចរាចរណ៍រួម (Global SSL & Traffic)

១៦.១ SSL រួម

មើលវិញ្ញាបនបត្រទាំងអស់របស់គេហទំព័រក្នុងកន្លែងតែមួយ ព្រមទាំងការព្រមានកាលបរិច្ឆេទផុតកំណត់។ ប្រើវាដើម្បីកុំឱ្យវិញ្ញាបនបត្រណាមួយផុតកំណត់ដោយអចេតនា។

១៦.២ ចរាចរណ៍រួម

ស្ថិតិចរាចរណ៍រួមគ្នាសម្រាប់គ្រប់គេហទំព័រ៖ ចំនួនសំណើ, លេខកូដ, bandwidth, cache hit និងភូមិសាស្ត្រ — ជួយមើលទិដ្ឋភាពធំនៃប្រព័ន្ធទាំងមូល។

ជំពូកទី ១៧ — ការកំណត់ប្រព័ន្ធ (Settings)

១៧.១ ទិដ្ឋភាពទូទៅ

ទំព័រការកំណត់រួមមានផ្នែកជាច្រើន ដែលរាយនៅខាងស្តាំ។ ខាងក្រោមនេះជាការពន្យល់ផ្នែកសំខាន់ៗ។

១៧.២ Appearance (រូបរាង)

  • Theme — ភ្លឺ/ងងឹត។
  • Brand colour — ពណ៌សម្គាល់របស់អង្គការ។
  • ភាសាផ្ទាំងបញ្ជា — បច្ចុប្បន្នគាំទ្រ អង់គ្លេស/ខ្មែរ (តាមការកំណត់)។

១៧.៣ Display & Data timezone (តំបន់ពេលវេលា)

កំណត់តំបន់ពេលវេលា (ឧ. Asia/Phnom_Penh) ដែលប្រើសម្រាប់៖

  • ការបង្ហាញពេលវេលានៅគ្រប់ទំព័រ។
  • ព្រំដែនកាលបរិច្ឆេទ និងចំណែកប្រចាំថ្ងៃក្នុងរបាយការណ៍។

១៧.៤ Account និង Users (គណនី និងអ្នកប្រើ)

  1. Account — កែឈ្មោះ, ប្តូរពាក្យសម្ងាត់ (ត្រូវបញ្ជាក់ពាក្យសម្ងាត់បច្ចុប្បន្ន)។
  2. Users — ចុច Add user បង្កើតអ្នកប្រើថ្មីជាមួយតួនាទី (role)។ អាចបិទ/បើកគណនី ឬបង្ខំឱ្យប្តូរពាក្យសម្ងាត់លើកដំបូង។
  3. Passkeys — ចុះឈ្មោះ Passkey (WebAuthn) សម្រាប់ចូលដោយគ្មានពាក្យសម្ងាត់។

១៧.៥ API protection (លំនាំដើមសម្រាប់ OpenAPI)

កំណត់របៀបលំនាំដើម (Off / Observe / Enforce) សម្រាប់ស្រទាប់ផ្ទៀងផ្ទាត់ OpenAPI ដែលប្រើនៅពេលគ្មានការកំណត់ជាក់លាក់តាម operation។

១៧.៦ Log retention (រយៈពេលរក្សាទុកកំណត់ហេតុ)

កំណត់រយៈពេលរក្សាទុកព្រឹត្តិការណ៍សុវត្ថិភាព និង access log។ កំណត់តម្លៃសមស្របនឹងទំហំឌីស និងតម្រូវការត្រួតពិនិត្យរបស់អ្នក។

១៧.៧ Custom error pages (ទំព័រកំហុសផ្ទាល់ខ្លួន)

កែទំព័រដែលអ្នកប្រើឃើញនៅពេលត្រូវទប់ស្កាត់ (403) ឬប្រឈមមុខ (challenge) ដើម្បីឱ្យស៊ីនឹងម៉ាករបស់អ្នក។

១៧.៨ API keys (កូនសោ API)

  1. ចុច Create key ដើម្បីបង្កើតកូនសោថ្មី។
  2. ចម្លង និងរក្សាទុកវាយ៉ាងសុវត្ថិភាព — វាបង្ហាញតែម្តងគត់។
  3. ប្រើវាសម្រាប់ការភ្ជាប់ពីប្រព័ន្ធខាងក្រៅ (SIEM, scripts ។ល។)។
ផ្នែកផ្សេងទៀត ការកំណត់ផ្សេងទៀតរួមមាន៖ Control-plane TLS (វិញ្ញាបនបត្រផ្ទាំងបញ្ជា), Observation mode (របៀបសង្កេតសកល — កត់ត្រាមិនទប់ស្កាត់), AI assistant, MCP (ភ្ជាប់ឧបករណ៍ជំនួយការ) និង Elasticsearch (បញ្ជូនកំណត់ហេតុបន្ថែម)។

ជំពូកទី ១៨ — ម៉ាស៊ីនសុវត្ថិភាព ដំណើរការយ៉ាងដូចម្តេច?

ជំពូកនេះពន្យល់លម្អិតអំពីអ្វីដែលកើតឡើងនៅពេលសំណើមួយមកដល់ Edge — ដើម្បីឱ្យអ្នកយល់ពីមូលហេតុនៃការសម្រេចចិត្ត និងរបៀបលៃតម្រូវប្រកបដោយទំនុកចិត្ត។

១៨.១ លំដាប់នៃដំណាក់កាល

  1. ទទួលសំណើ — Edge ទទួលសំណើ HTTP/HTTPS និងកំណត់អត្តសញ្ញាណគេហទំព័រតាមដែន (Host)។
  2. Canonicalization — URL, query, cookies និង headers ត្រូវបានធ្វើឱ្យមានទម្រង់តែមួយ។ ឧទាហរណ៍៖ %2e%2e%2f ត្រូវបាន decode, /a/../b ត្រូវបានបង្រួម។ នេះជាមូលដ្ឋានដ៏សំខាន់ ព្រោះអ្នកវាយប្រហារចូលចិត្តប្រើការសរសេរខុសៗគ្នា ដើម្បីបញ្ឆោតប្រព័ន្ធ។
  3. ច្បាប់ IP និងបញ្ជីទប់ស្កាត់ — បើ IP ស្ថិតក្នុងបញ្ជីទប់ស្កាត់ (ឧ. auto-block) វាត្រូវបានបដិសេធភ្លាម មុន engine។
  4. Signature Lane — ស្កេនលំនាំដោយ Aho-Corasick៖ លំនាំកម្រិតទប់ស្កាត់ (payload ច្បាស់) និងលំនាំកម្រិតកត់ត្រា (ពាក្យសង្ស័យ)។
  5. ច្បាប់គ្រប់គ្រង — ច្បាប់ ១៣ គ្រួសារបន្ថែមពិន្ទុ anomaly។ បើពិន្ទុលើសកម្រិត → block។
  6. ច្បាប់ផ្ទាល់ខ្លួន និង SecLang/CRS — កន្សោមរបស់អ្នក និងច្បាប់ CRS ដែលបាននាំចូល។
  7. API Schema — បើបើក សំណើត្រូវបានផ្ទៀងផ្ទាត់តាម OpenAPI (តាមរបៀបរបស់ operation)។
  8. Rate limit / Bot / Geo — ដែនកំណត់អត្រា និងគោលនយោបាយបុត/ភូមិសាស្ត្រ។
  9. ការលើកលែង (Exclusions) — កញ្ចប់ និង target exclusions ត្រូវបានអនុវត្ត ដើម្បីកាត់បន្ថយការបាញ់ខុស។
  10. សេចក្តីសម្រេច — Allow (បន្តទៅ origin), Monitor (កត់ត្រា បន្តទៅ origin) ឬ Block (ឆ្លើយតបទំព័រកំហុស)។

១៨.២ ការកត់ត្រា និងមូលហេតុ

រាល់ការសម្រេចចិត្តត្រូវបានកត់ត្រាជាមួយព័ត៌មានគ្រប់គ្រាន់ ដើម្បីឆ្លើយសំណួរ «ហេតុអ្វី?»៖ ច្បាប់ណាបាញ់, ពិន្ទុប៉ុន្មាន, ផ្នែកណានៃសំណើ (target) និងការលើកលែងណាត្រូវបានពិចារណា។ ប្រើ Logs → why resolver ដើម្បីមើលវា។

១៨.៣ ដែនកំណត់ដែលចេះគ្រប់គ្រង (Bounded work)

  • ចំនួនការរកឃើញក្នុងសំណើមួយមានដែនកំណត់។
  • ការត្រួតពិនិត្យ body មានថវិកា (budget) — មិនអានគ្មានទីបញ្ចប់។
  • នៅពេលលើសដែនកំណត់ ប្រព័ន្ធ ចុះកម្រិតជារចនាសម្ព័ន្ធ (structured degradation) ជំនួសការបរាជ័យទាំងស្រុង។

១៨.៤ រូបភាពស្ថានភាព (Snapshots) និងភាពស៊ីសង្វាក់

រាល់គេហទំព័រមាន runtime snapshot ដែលជា រូបភាពមិនអាចកែ (immutable) នៅខាងក្រោយ ArcSwap។ ន័យថា៖ នៅពេលអ្នកអនុវត្តការផ្លាស់ប្តូរ សំណើដែលកំពុងដំណើរការនឹងបន្តប្រើ snapshot ចាស់រហូតដល់ចប់ — គ្មានសំណើណាមួយឃើញស្ថានភាព «ពាក់កណ្តាល» ឡើយ។

១៨.៥ របៀប Shadow (ប្រៀបធៀបម៉ាស៊ីន)

នៅពេលអ្នកជ្រើស engine mode = shadow ម៉ាស៊ីនទាំងពីរ (ថ្មី និងចាស់) ដំណើរការជាមួយគ្នាលើសំណើដូចគ្នា ហើយលទ្ធផលត្រូវបានកត់ត្រាជា៖ «យល់ស្រប», «ម៉ាស៊ីនថ្មីតឹងជាង» ឬ «ម៉ាស៊ីនថ្មីធូរជាង»។ នេះជាវិធីសុវត្ថិភាពបំផុតក្នុងការផ្លាស់ប្តូរម៉ាស៊ីន៖ សង្កេតជាមុន រួចទើបប្តូរ។

ជំពូកទី ១៩ — ប្រតិបត្តិការ និងការដោះស្រាយបញ្ហា

១៩.១ ការបម្រុងទុក និងស្តារទិន្នន័យ (Backup / Restore)

ទិន្នន័យទាំងអស់ស្ថិតក្នុង PostgreSQL។ ការបម្រុងទុកសំខាន់បំផុតគឺ database៖

docker exec varman-postgres pg_dump -U varman varman | gzip > varman-backup.sql.gz

ដើម្បីស្តារ៖ បង្កើត database ទទេម្តងទៀត រួច gunzip -c varman-backup.sql.gz | docker exec -i varman-postgres psql -U varman varman បន្ទាប់មក restart Control Plane។

១៩.២ ការធ្វើបច្ចុប្បន្នភាព (Upgrade)

  1. បម្រុងទុក database ជាមុន (ខាងលើ)។
  2. ទាញយក image ថ្មី៖ docker pull sovichetra/varmanwaf:latest។
  3. ដំណើរការឡើងវិញ៖ docker compose up -d។
  4. ពិនិត្យសុខភាព៖ បើក https://<host>:9080/healthz និងមើលកំណែនៅ Settings → About។
