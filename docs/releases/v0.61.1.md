# VarmanWAF v0.61.1 - Single-path specs: the base-prefix fix

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.61.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.61.1`

The live run of the operation-controls E2E found a pre-existing defect in
the OpenAPI layer: with a spec declaring **one path**, the inferred base
prefix was that whole path, so every request to it stripped to nothing and
read as `api.unknown_operation` - the declared operation (and its required
parameters) never matched. 0.61.0's image was never published.

## What this round changes

- **The inferred prefix never consumes a path**: `common_prefix` truncates
  the shared run so at least one segment stays with every declared path
  (a single-path spec therefore gets no inferred prefix at all).
- **Inferred prefixes are stripped from the operations**: a servers-based
  prefix never appears in declared paths, but an inferred one does - the
  parser now removes it from the operation segments so matching stays
  relative, and specs sharing a real prefix (`/api/orders` + `/api/items`)
  validate cleanly while undeclared paths inside the prefix report
  `api.unknown_operation` and paths outside stay untouched.
- **Tests pin both**: the single-path spec matches its operation and
  reports the missing required parameter; the two-path spec keeps `/api`,
  validates its operations, reports unknown inside the prefix and ignores
  paths outside it.
