# VarmanWAF v1.2.12 — certificate reload, upstream security fixes, ACME backoff

**Release date:** 2026-10-28
**Images:** `sovichetra/varmanwaf:1.2.12`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.12`

Combined release: the certificate-reload fix for the calendar 525, the first
batch of upstream v0.32.2 security fixes, and ACME retry scheduling.

## Certificate-only changes now reload the edge

The agent’s change hash was the **first site’s** bundle hash. An all-in-one
agent receives every site in one config, so uploading a certificate for any
other site changed the full configuration but not the value the data-plane
watcher compared. The certificate row was active and the PEM/key were valid,
but the edge kept serving the old SNI table; Cloudflare returned **525** until
the container was restarted.

- `CachedRules` now carries `data_plane_hash`: the outer full-`SiteConfig`
  fingerprint on a full push, or the changed bundle’s hash on a single-site
  `SyncRules` push.
- The reload watcher compares `data_plane_hash()`; the reported `config_hash`
  used for delta sync is unchanged.
- Regression test: two sites, change only the second bundle, assert the
  per-site hash stays put and the reload fingerprint moves.

This is the `calendar.unity-workspace.com` case: a valid Cloudflare Origin CA
certificate (`*.unity-workspace.com`, key matches) was uploaded but never
loaded. A restart presented it and the site returned **200** through Cloudflare
Full (strict); v1.2.12 makes that automatic.

## Upstream security fixes (PingWAF v0.32.2 batch 1)

- **Unauthenticated API-key prefix panic fixed.** `authenticate_api_key`
  sliced the first eight bytes of the presented key. A multi-byte character on
  that boundary panicked, and release builds abort on panic, so one
  `RegisterAgent` call could stop the control plane. The prefix is now
  ASCII-checked and sliced with `get`.
- **Cross-tenant log read fixed.** `GET /logs/security` and `/logs/access`
  with an explicit `site_id` returned that site’s rows without checking
  ownership for non-admin callers. The filter now goes through
  `load_site_read`, which answers 404 for an invisible site.

## ACME scheduling

- New orders are checked on **every** one-minute ACME tick instead of every
  tenth tick, so a newly created site is attempted within a minute.
- Failed certificate/domain pairs back off **5m → 15m → 30m → 1h → 6h**, so a
  persistent DNS/HTTP misconfiguration cannot exhaust CA quotas or hammer the
  notification channel.
- Success (or a certificate that is already valid) clears the backoff.

## Upstream delta status

The full PingWAF delta from v0.25.10 (`aa597371`) to v0.32.2 (`351db15e`) is
274 commits and roughly 15k lines in the vendored foundation. This release
ports the certificate reload, the two critical v0.32.2 security fixes and the
ACME scheduler. The remaining areas are tracked in
[`docs/upstream-update-plan.md`](../upstream-update-plan.md) and are not
silently merged:

- dependency advisories and vendored `pingora-header-serde` (zstd/header
  serde);
- WAF body staging bounds, UTF-16/multipart coverage and memory caps;
- OIDC, visitor auth, encrypted backups/restore, new dashboard pages;
- per-site downstream timeout, refresh-token single use, rate limits;
- the newer Pingap plugin-registration/style refactor.

Those need their own batches, migrations and E2E; merging them wholesale would
risk the production data plane.

```bash
docker compose pull varman

curl -sk https://localhost:9080/api/v1/version   # -> 1.2.12
```

No migration and no configuration change.
