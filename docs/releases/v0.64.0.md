# VarmanWAF v0.64.0 - Response-shape learning

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.64.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.64.0`

The last piece of the API pipeline: the learner now reads **response**
bodies too, per status class, with the same discipline as the request side.

## What this round brings

- **Response structures per status class**: the learn pass merges the
  stored response bodies into `2xx` / `3xx` / `4xx` / `5xx` schemas (keys,
  types, presence counts - values are never read), stored on the learned
  row (`response_schema`, `response_samples`). Truncated or non-JSON
  bodies are skipped and counted in the summary (`response_samples`,
  `response_skipped`), never guessed at.
- **The OpenAPI draft gains real responses**: one entry per learned class
  (`200`, `400`, ...) with `x-observed-class`, the JSON schema and the
  structures-only description. When no response body was captured the
  draft keeps an honest default note - "response shapes are learned only
  when the agent captures response bodies" - instead of inventing shapes.
- **Console**: the learned table gains a **Responses** column (samples +
  the classes seen); the learn summary reports response samples; the note
  states when response learning applies.

## A trap caught on the way (worth recording)

`sqlparser` (an external crate) sits at **0.63.0** - the same string the
workspace version used. The pre-bump count check (20 internal entries) held,
so nothing was corrupted, but a blind `replaceAll` for this round would
have bumped the external crate. The bump is now **line-scoped** (workspace
version + `pingap-*` path deps only, externals explicitly kept), and this
release's Cargo.toml proves it: 20 internal entries at `0.64.0`,
`sqlparser` still at `0.63.0`.
