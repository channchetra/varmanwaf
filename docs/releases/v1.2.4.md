# VarmanWAF v1.2.4 — the embedded agent serves every site, not one admin's

**Release date:** 2026-10-27
**Images:** `sovichetra/varmanwaf:1.2.4`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.4`

Patch release for an all-in-one scoping bug that could leave a site with no
edge configuration and no certificate.

## The bug

In all-in-one mode the data plane is an embedded agent registered with the
bootstrap API key. An unbound agent was scoped to **the sites owned by the
user that issued its API key**. The bootstrap key belongs to whichever admin
was seeded first, so the embedded agent only ever received that account's
sites.

A site created by a different admin therefore:

- was missing from the data plane's rule cache, so the proxy did not serve it;
- never had its certificate entry loaded, so TLS handshakes for its hostname
  failed with `no match certificate`;
- could not complete an ACME order, because the certificate config never
  reached the agent — the row stayed `pending` and was eventually marked
  `failed` by the stale-order sweeper.

At the edge this surfaced as Cloudflare **525 SSL Handshake Failed**: the
origin listener on 443 had no certificate for that SNI at all. Restarting the
container or re-issuing the certificate did not help, because the site was
never in the agent's scope.

## The fix

- An unbound agent holding the all-in-one bootstrap key now receives **every
  site on the instance**, matching what an embedded data plane must serve.
- The same rule is applied in both places that resolve an agent's scope: the
  gRPC `visible_sites` path (initial `register_agent` and `GetSiteConfig`) and
  the `UpdateSite` push path, so a config change reaches the edge even when
  the site belongs to another admin.
- Agents bound to a single site and agents registered with ordinary or
  enrollment keys keep their existing owner-scoped behaviour.
- Added a regression test that pins the scope rule: only the bootstrap key
  serves every site.

## Verification

- `cargo test -p varman-control --lib grpc::` → **40 passed**.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.4
```

No migration and no configuration change. Existing site ownership does not
need to be reassigned.
