# VarmanWAF v0.55.0 - Geo and ASN data from ipverse

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.55.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.55.0`

Geo and ASN enforcement now runs on ranges downloaded from **ipverse** -
the only source. The country data that used to sit inside the edge's
embedded table no longer decides anything, and the ASN list that v0.53.1
surfaced as a silent no-op is real.

## What this round brings

- **`ip_datasets`**: one synced row per country (`rir-ip`:
  `country/<cc>/ipv{4,6}-aggregated.txt`) or ASN (`as-ip-blocks`:
  `as/<n>/ipv{4,6}-aggregated.txt`). Syncs are on demand from the console
  and refreshed daily by the subscription scheduler; a failed sync keeps
  the previous ranges and records the error.
- **`GET/POST /ip-datasets`** (admin): the referenced keys, their sync
  state, and the sync actions. A successful sync **re-pushes every site
  whose geo policy lists the key**, so "synced" and "applied" never drift.
- **Range-based geo enforcement**: the bundle now carries
  `country_ranges`/`asn_ranges` for the listed keys plus `missing_keys`;
  the plugin matches the client address with the same `IpRules` matcher the
  IP access rules use. `block_list`, `allow_list` (outside the ranges =
  denied), `block_unknown` (outside the listed countries = denied, stated
  in the UI) and the `log`/monitor action all work on ranges.
- **Honest surfaces**: a listed key without synced data is **not enforced**
  and says so - the geo tab shows per-key status (IP data card, ASN and
  country notices), the analysis tool names the missing keys and states
  that the country it prints is a display label from the built-in table.
- **Transport**: site bundles with country datasets exceed tonic's 4 MiB
  default; both ends now use a 64 MiB limit
  (`varman_protocol::MAX_GRPC_MESSAGE_BYTES`).
- **Access control -> Geo** gains the **IP data (ipverse)** card: every
  referenced country/ASN, synced-at, range counts, per-key sync, sync-all.

## Verification at release

- `cargo fmt --check` exit 0; control tests **368** (new: key
  normalisation, ipverse URL builders, range merging); plugin tests **198**
  (rewritten geo suite: country ranges block, allow list, block unknown,
  ASN ranges, monitor, missing keys never deny); agent **41**; clippy
  `-D warnings` clean; web tsc/eslint/vite clean, 20/20 unit tests.
- Live E2E (ipverse script): with `US` and `13335` listed but unsynced the
  analysis is `pass/none` with both keys in `missing_keys`; one
  `sync-referenced` call downloads them from ipverse (US: tens of
  thousands of ranges, AS13335: its announced prefixes), reports
  `pushed_sites`, and the analysis then decides `block/geo` for `8.8.8.8`
  (US ranges) and for `1.1.1.1` (AS13335 ranges, named in `asn_matches`);
  the geo policy is restored afterwards.
- Note on the edge path: range matching through the full plugin request
  path is covered by the plugin tests; the bundle→agent delivery is
  verified by the push count and the analysis reading the same stored
  ranges.
