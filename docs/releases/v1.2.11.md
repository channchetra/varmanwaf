# VarmanWAF v1.2.11 — certificate-only changes reload the edge

**Release date:** 2026-10-28
**Images:** `sovichetra/varmanwaf:1.2.11`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.11`

Patch release for certificate uploads that never reached the running data
plane.

## The bug

The agent reports a single `config_hash` for delta sync. That value was the
**first site's** rule-bundle fingerprint. An unbound all-in-one agent receives
every site in one config, so a change to a site that was not first — uploading
a certificate, selecting a different certificate, editing an origin — changed
the full configuration but not the value the data-plane watcher compared.

The result: the certificate row was `active` and the PEM/key were valid, but
the edge kept serving the old SNI table. Cloudflare returned **525** because no
certificate was loaded for that hostname. A container restart loaded it.

This is exactly what happened to `calendar.unity-workspace.com`: a valid
Cloudflare Origin CA certificate (`*.unity-workspace.com`, key matches) was
uploaded, but the data plane never reloaded. After a restart the origin
presented the certificate and the site returned **200** through Cloudflare
Full (strict).

## The fix

- `CachedRules` now carries a separate `data_plane_hash`:
  - the outer full-`SiteConfig` fingerprint on a full push, so **any** site's
    change moves it;
  - the changed bundle's fingerprint on a single-site `SyncRules` push.
- The reload watcher compares `data_plane_hash()` instead of the per-site
  `config_hash()`. The reported `config_hash` used for delta sync is unchanged.
- Caches written before this release fall back to the old hash and are updated
  on the next full config, so upgrades need no migration.

## Verification

- New regression test: two sites, change only the second site's bundle, assert
  the per-site hash stays put and `data_plane_hash` moves.
- `cargo test -p varman-agent --lib` → **44 passed**.
- `cargo check --bin varman` → clean.
- Production check after the manual restart: `certificates loaded` includes
  `61def2a7-..._cert`; origin prints the Cloudflare Origin CA certificate;
  `https://calendar.unity-workspace.com/` returns **200**.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.11
```

No migration and no configuration change. A certificate upload after the
upgrade should reload the edge without a restart; watch for
`data plane: rule change detected` in the log.
