# VarmanWAF v0.63.0 - One protection surface: the Settings tab folds in

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.63.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.63.0`

The last old-style screen in the protection flow: the site's **Settings**
tab (WAF grading knobs, custom layers, monitor lists) sat beside the Policy
tuning surface. It now lives inside it - one protection surface per site.

## What this round brings

- **The Settings tab is gone**: the site's own posture panel (advanced mode,
  engine mode, virtual patches + OpenAPI spec, per-category/stack monitor
  switches) mounts as the **Site posture** section of the Policy tuning
  page, with its callout explaining that an assigned policy overrides these
  knobs.
- **Clearer section names**: the rail now reads *Policy summary -> Site
  posture -> Effective posture -> Rule exceptions -> Exclusion packages ->
  Preview and apply -> Version history* (the old "CRS protection & posture"
  label, which pointed at the read-only effective card, is now "Effective
  posture" - distinct from the site's own knobs).
- **Legacy links keep working**: `?tab=settings` (alongside `?tab=policy`
  and `?tab=exclusions`) resolves to the tuning surface; the Protection tab
  strip is now Overview / Rules / CC / Policy tuning.

## Verification at release

- Web `tsc`, eslint, `vite build` clean; 20/20 unit tests; the new markers
  (`Site posture`, `Effective posture`) present in the built bundle.
- Live E2E (tuning script): the Protection page serves, the tuning tab
  renders with the seven nav sections, and the legacy `?tab=policy` /
  `?tab=exclusions` links resolve into it; the settings endpoints behind
  the posture panel answer.
- No server changes: the binary is the v0.62.0 engine with the new console
  embedded.
