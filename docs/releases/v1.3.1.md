# VarmanWAF v1.3.1 — port-forward listener rebind

**Release date:** 2026-10-28
**Images:** `sovichetra/varmanwaf:1.3.1`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.3.1`

Patch release for the v1.3.0 TCP port-forward feature.

## The bug

Editing a forward's allowlist or target stops the old listener and starts a
new one. `JoinHandle::abort()` completes asynchronously, so the immediate
`TcpListener::bind` for the same listen port raced the old socket and failed
with `EADDRINUSE`. The retry was 30 seconds, so an allowlist/target edit took
up to half a minute to take effect.

## The fix

- When a changed rule is stopped, rebinding is deferred by one reconcile cycle
  (2 seconds), giving the aborted task time to drop its listener.
- A genuine bind failure is retried after 5 seconds instead of 30.

## Verification

- `cargo test -p varman-agent --lib port_forward` → **3 passed** (allowlist
  parsing, rule change detection, cache carry-over).
- Production end-to-end with v1.3.0: denied source → connection reset; allowed
  source → **HTTP 200** through the forward; delete → listener stopped.
- v1.3.1 shortens the allowlist/target edit window from 30 s to about 2 s.

v1.3.1 includes v1.3.0 (TCP port forwarding) and v1.2.12 (certificate reload,
upstream security batch 1, ACME backoff).

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.3.1
```

No migration and no configuration change.
