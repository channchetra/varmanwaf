# VarmanWAF v0.42.0 - wafLinkage wired: category switches keep their rule families in step

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.42.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.42.0`

The `wafLinkage` helpers ported in batch 4b were groundwork - upstream
shipped the module with no production caller. This round wires them into
the one surface where the two lists travel as a single payload: the site's
**Web Protection settings**.

## What this round brings

- **A category toggle moves both lists.** Switching a category to
  monitor-only now sends one `PUT` carrying `monitor_categories` *and* the
  family's `monitor_managed_rules` resolved from the managed-rule
  catalogue - literal-expression family rules only react to the per-rule
  list, so the category flag alone used to leave them enforcing. Switching
  the category back resets those family overrides, exactly the unit-tested
  `applyCategoryLinkage` contract (6 tests, batch 4b).
- **Non-destructive when the catalogue is unavailable.** The category
  switches disable while the catalogue loads; if it has failed, a toggle
  never clears unknown family ids - the linkage only removes ids it can
  actually see, so the per-rule list is left untouched rather than guessed
  at.
- **Optimistic updates extended** to the per-rule list, so the toggle does
  not flicker back on refetch.
- **Honest hints on both surfaces** (the behaviour is stated, not left
  implicit):
  - the site panel explains the linkage, the reset-on-switch-back
    semantics and why the switch waits for the catalogue;
  - the policy engine form (Policies -> engine layer) states that a
    policy's family rules are monitored through the CRS layer's rule list,
    and that there is **no cross-layer auto-write** - policy layers stay
    independent with their absent-means-inherit semantics.

## Verification at release

- `npx tsc -b`, `npx vite build` and eslint clean; bundle markers for both
  hints; web unit suite 15/15 (the linkage contract itself predates this
  round).
- Live E2E (linkage script): the linked payload persists
  (`GET /waf/settings` returns both arrays), the site's effective config
  reflects the family rules once the category is monitor-only, and
  switching back restores the previous settings **exactly**; the
  catalogue's category-to-family mapping used by the script is read from
  `GET /managed-rules`, not hard-coded.
