# VarmanWAF v0.35.0 - Upstream batch 3a: verified-bots DNS + spoof-resistant bot checks

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.35.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.35.0`

Upstream sync continues. Batch 3 (WAF engine + plugin) is split like batch 2
was: **3a** lands the verified-bots work now, **3b** (plugin body staging)
and **3c** (challenge/error pages) follow.

## What this round brings

- **Verified bots, spoof-resistant** (upstream `bot-ip-blocks`-style
  hardening, ported into our plugin):
  - **DNS verification** (new `pingap-plugin/src/bot_dns.rs`, upstream
    module): a user agent claiming a well-known crawler family
    (Googlebot/Bingbot/YandexBot/DuckDuckBot/Baiduspider) is only trusted
    after the client IP proves it: the PTR record must live in the
    operator's own zones **and** a forward lookup of that hostname must
    return the client IP. Verdicts are cached per (IP, family) with tiered
    TTLs (confirmed 1 h, refuted 10 min, outage 1 min), so a resolver
    outage degrades to the user-agent verdict instead of blocking on it -
    stated, not guessed.
  - **IP-range verification**: client IPs inside the configured
    verified-bot list pass regardless of user agent. The control plane
    already expands the referenced IP group into `verified_bot_ranges`
    (batch 2 wired the proto + agent); the plugin now honours it.
  - **Site UI**: the Bot Protection page gains a "Verified bots" card -
    IP-range verification toggle + list picker (with a pointer to the IP
    list catalog from v0.33.0, e.g. "All crawlers" refreshed daily), DNS
    verification toggle, and an explainer of the degradation rule.
- **Batch-3 scope decisions (recorded honestly)**:
  - The upstream engine posture/grading delta
    (`monitor_managed_rules`/`monitor_custom_rules` + downgrade tests) is
    **already in this fork** (P2/P3 integrated it), so nothing was ported
    there; the upstream managed-rule catalogue is likewise superseded by
    our larger `VARMAN-` catalogue.
  - Plugin body staging (the `waf.rs` restructure) and challenge/error
    pages are deliberately deferred to **3b/3c** so each sub-batch ships
    as a whole.

## Verification at release

- New tests: `bot_dns` unit tests (family matching, dot-boundary suffix
  matching, tiered TTLs - upstream's own) and a plugin test proving a
  client IP inside a verified range passes while a scripted UA outside it
  is denied, with malformed range entries skipped rather than fatal.
- `cargo test --workspace` green; clippy `-D warnings` clean; `tsc -b &&
  vite build` clean.
- Live E2E: a spoofed Googlebot user agent passes on the whitelist alone;
  enabling DNS verification turns the same request into the configured
  action (refuted); disabling the whitelist but enabling IP-range
  verification with a group containing the probe network makes it pass
  again; with both off it is denied. The site's configuration is restored
  afterwards.
