# VarmanWAF v0.59.0 - Argument-level exclusions

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.59.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.59.0`

The engine capability that makes exclusion packages precise: a rule
exclusion can now name **one member** of a source instead of the whole
source. This is the prerequisite for importing CRS-style upstream
exclusions (most of which are argument-level), and it is useful today for
custom rules.

## What this round brings

- **Named exclusion targets** in the engine: `query:q`, `body:content`,
  `cookie:session`, `header:x-api-key` remove exactly that member from the
  addressed rule's evaluation view while everything else stays inspectable.
  - Query filtering rewrites the full-URI view (the query is derived from
    it), so `http.request.uri.query` and `http.request.uri.full` see the
    filtered query.
  - Body filtering handles urlencoded bodies (pair removal) and JSON bodies
    (top-level keys and dotted paths); a body that cannot be addressed
    safely is left untouched rather than guessed at.
  - Header and cookie names match case-insensitively.
- **Validation extended**: package entries accept named targets and now
  address **custom rule ids** as well as managed ones (the actual use case:
  an operator rule over a query/body member); the policy override validator
  accepts the named forms too.
- **A real bug fixed on the way**: `EvalContext::header` compared header
  names case-sensitively despite its documented case-insensitive contract
  (production only worked because the `http` crate lowercases names);
  the lookup now matches the contract.
- **Root prefix fix**: attaching a package at `/` stored an empty prefix
  that the engine skips; the root prefix is now preserved as `/`.
- Console: the exclusion packages panel states the named-member forms.

## Note on scope

Managed rules that consume anomaly **scores** (`cf.waf.score.*`) remain
unaffected by exclusions - their input is the Stage-1 signature pipeline,
which exclusions deliberately do not touch. Named exclusions apply to rules
whose expressions read the request fields directly (headers, cookies,
query, body), which is exactly where custom rules and the upcoming upstream
import operate.
