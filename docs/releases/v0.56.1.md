# VarmanWAF v0.56.1 - Exclusion packages: the cache-leak fix

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.56.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.56.1`

v0.56.0 was tagged in git but its image was never published: the first live
run of the exclusion-package E2E did not show the exclusion taking effect,
and the hunt found a real defect in the agent cache. Operators get the fix
in the **0.56.1** image.

## What the live run found

The agent's proto-to-cache conversion put **every** `rule_target_exclusions`
entry into the site-wide exclusion map, including entries that carry a path
prefix. A package exclusion attached at `/.git` therefore applied
**site-wide** in the edge cache - the opposite of "scoped to a prefix" - and
the path-scoped list the engine actually consults was not the one being
populated from the bundle.

## What this round changes

- **The cache conversion filters by prefix**: entries with a path prefix go
  only into `path_target_exclusions`; site-wide entries stay in the map. A
  package exclusion can never widen beyond its prefix.
- **A regression test pins it**: proto with one scoped and one site-wide
  entry -> one path-scoped entry, one map entry (`varman-agent`).
- **A data-plane test pins the whole chain**: bundle -> agent cache -> site
  engine -> `/.git/config` served under the prefix, `/.svn/config` blocked
  outside it (`pingap-plugin`).
- **Observability**: the compiler logs how many exclusions a site's
  bindings produced (`exclusion packages compiled into the site bundle`),
  so "attached but not applied" is visible in the control-plane log.

- `cargo fmt --check` exit 0; control tests **371**; plugin **200**; agent
  **42**; engine **494**; clippy `-D warnings` clean; web unchanged from
