# VarmanWAF v1.4.3 — certificate rotation without restarts

**Release date:** 2026-11-27
**Images:** `sovichetra/varmanwaf:1.4.3`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.4.3`

> **Superseded:** [v1.4.4](./v1.4.4.md) includes these fixes and also
> sanitises NUL bytes in stored request/response bodies. Deploy v1.4.4.

Fixes the seven-day telemetry outage of 2026-11-20 → 2026-11-27 and the
stream-inspection issues found in the 1.4.2 review.

## What happened

The control-plane ACME certificate expired at **2026-11-13 22:59 UTC** and was
never renewed. The running process kept its existing gRPC connection, so data
kept flowing until the next restart on **11-20 05:09**, when the agent tried to
connect again, rejected the expired certificate, and could no longer ship
anything. Its in-memory buffer filled and dropped every access log and security
event for seven days.

Three defects combined:

1. The ACME request stopped being scanned after 11-08; no renewal was
   attempted, and nothing alerted.
2. The gRPC listener snapshotted its TLS pair at startup, so a renewed
   certificate could not reach port 9090 without a restart.
3. A single NUL byte in a log entry made PostgreSQL reject the whole
   `insert_many` batch; the agent retried the same poisoned batch forever.

## Fixes

### gRPC TLS follows the active certificate

The gRPC listener now accepts connections through a per-connection
`rustls::TlsAcceptor` built from `ControlPlaneTls`'s reloadable resolver, with
ALPN `h2`. A certificate installed by the ACME installer is used by the next
handshake — no restart. Explicit `grpc_tls_cert`/`grpc_tls_key` files keep
working (loaded once, as before).

`varman-control/src/tls.rs` (`grpc_acceptor`, `grpc_incoming`),
`varman-control/src/lib.rs`.

### Renewal watchdog

Every 15 seconds the management-certificate task checks the installed
certificate. With less than **48 hours** left it re-arms the ACME request (the
same call the manual *Retry* button makes), at most once every six hours, and
raises a `cert.expiring` / `cert.expired` alert once per fingerprint. A fresh
certificate clears both gates.

`varman-control/src/management_cert.rs`.

### NUL bytes no longer poison a log batch

`optional()` and `truncate()` in the log mappers replace `0x00` with `U+FFFD`
before the insert. A scanner path such as `/x%00y` now stores one sanitised row
instead of failing the batch and losing every entry behind it.

`varman-control/src/grpc/control_plane.rs`.

### Stream inspection corrections

From the 1.4.2 review:

- **One event per rule per connection.** A monitor site no longer writes a
  security event for every matching WebSocket message; one busy connection had
  produced 633 rows over two hours. Blocking findings still stop on the first
  one.
- **Disabled WAF, observation mode and unsynced bundles no longer enforce.**
  `stream_enforcement` now uses `EngineChoice::Disabled`, `observation_mode`
  and `resolve_mode`, instead of re-deriving enforcement from raw fields. An
  agent deployment whose domain has no synced bundle also stops falling back
  to the plugin's block mode.
- **Engine aliases match the request path.** `enforce`, `observe` and `base`
  are accepted exactly as the request path accepts them; previously `enforce`
  silently disabled stream enforcement.
- **Protocol failures always close the stream.** After a malformed frame the
  boundaries are unknown; continuing produced an uninspected connection on
  monitor sites.
- **No request-counter inflation.** A monitor finding no longer increments
  `requests_total` once per message.

`pingap-plugin/src/waf.rs`, `pingap-plugin/src/waf_stream.rs`.

### Known limitations (unchanged)

- A **Block + legacy** site keeps WebSocket streams in monitor-only mode: the
  stream inspector is the Varman pipeline, and an operator who selected
  `legacy` has not opted into its verdicts. Use Block + Varman for stream
  enforcement.
- Per-site `monitor_categories` and path exclusions are not yet applied to
  stream payloads; the stream scanner uses a fixed detector set. No current
  production site both enforces streams and configures monitor categories.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.4.3
```

No migration is required.

Check that the agent reconnects:

```bash
docker logs --since 5m varman 2>&1 | grep -E "Connected to control plane|transport error"
```
