# VarmanWAF v0.34.0 - Rule authoring depth: action cards, a real request path, and draft testing

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.34.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.34.0`

The rule editor now explains itself the way the studied product's does - and
tests the draft before it is saved.

## What this round brings

- **Action cards instead of an action dropdown.** Block request / Challenge
  the browser / JavaScript challenge / Record match / Exempt this request,
  each with a chip and a one-line description written from the engine's own
  semantics. Picking one updates the path preview immediately.
- **Actual request path.** A three-step strip under the condition builder:
  *your conditions match* -> *this rule: <action>* -> *result*, where the
  result text respects the runtime mode (`off` short-circuits; `monitor`
  downgrades every action to "recorded as a monitor event"; `block` denies
  with the 403 block response *and skips later rules*; `allow` stops
  evaluation for the request). No invented behaviour - each sentence maps to
  a branch the evaluator really has.
- **Test the draft before saving** (`Test rule`, also in the dialog footer):
  the same site-scoped engine the edge runs - policy rules, the site's saved
  rules, tuning, imported CRS and SecLang patches - evaluates a sample
  request with the draft **on top**, and the result names the verdict, the
  score, every matched rule (the draft is badged `draft`), tuning notes, and
  what was *not* simulated (rate limits, IP/geo, bot - edge decisions that
  need request history).
- **Drafts that cannot compile say so.** A broken expression or unknown
  action in a draft produces a note ("draft rule 'X' was not evaluated:
  <parser error>") instead of silently testing as "no match". This is why
  `policy_test::compile_rule_result` exists next to `compile_rule`.
- Backend: `POST /api/v1/policies/test` accepts `draft_rules` (validated,
  evaluated after policy and site rules, reported with source `draft`) -
  existing callers are unaffected.

## Verification at release

- New unit test: draft compile errors are reported (broken expression,
  unknown action) and valid drafts compile with their `draft:<n>` id.
- `cargo test --workspace` green; clippy `-D warnings` clean; `tsc -b &&
  vite build` clean.
- Live E2E: a draft rule blocks its path in the tester with source `draft`;
  switching the same draft to `monitor` yields a monitor verdict; a draft
  with a broken expression reports the compile error in the notes; a
  SecLang/CRS draft test still reports imported rules; saving the rule and
  probing the edge confirms the tester's verdict (403), then everything is
  cleaned up.
