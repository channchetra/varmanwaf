# VarmanWAF v0.47.0 - Scheduled reports: cron delivery through the alerting channels

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.47.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.47.0`

The last piece of the report system: a cron-style schedule that generates
the interception report and delivers it through the existing alerting
channels - e-mail channels attach the HTML file, chat channels receive the
summary message.

## What this round brings

- **Schedule** (saved with the report settings): daily / weekly / monthly
  at HH:MM **UTC**, a weekly weekday or monthly day (1-28, so no month can
  skip a firing), the covered window (1-92 days, ending at the trigger
  time), scope (all sites / one) and the action filter - the same filters
  the manual report uses.
- **Armed on save**: saving with the schedule enabled sets `last_fired =
  now`, so the first report goes out at the next occurrence instead of
  immediately catching up on a past-due slot; one occurrence never fires
  twice (the tick records each firing).
- **Delivery through the alerting system** as a new `report.scheduled`
  event: the summary message carries the headline numbers; **e-mail
  channels attach the HTML report** (lettre multipart), every other
  channel kind delivers the message alone. The event lands in the alert
  history every run - delivery failures included - exactly like every
  other alert. No new per-event toggle: like the test button, the type is
  governed by the master notification switch and channel subscriptions
  (`allows()` delivers unknown types under the master switch).
- **Send now**: generates and dispatches immediately with the schedule's
  window/scope, without touching `last_fired` - the honest "test" button
  for the whole path.
- The scheduler is a 60-second tick beside the alert evaluator; all report
  aggregations now take the database handle directly (the scheduler has no
  `AppState`), so manual and scheduled reports share one code path.
- Tests: `last_due` walk-back for daily/weekly/monthly (including the
  monthly rollover), schedule validation bounds, and the existing report
  suites - control now **360**.
