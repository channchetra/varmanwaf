# VarmanWAF v0.22.1 — upstream sync round 2a (agent + protocol model)

**Release date:** 2026-10-13 · **Images:** `sovichetra/varmanwaf:0.22.1`,
`sovichetra/varmanwaf:latest` · **Tag:** `v0.22.1`

Second upstream update round, first half: the **protocol and agent model**
from PingWAF v0.25.10 is ported. No enforcement behaviour changes; the edge
and control plane keep working exactly as before while gaining the data model
the later batches build on. Plan and batch order:
[`docs/upstream-update-plan.md`](../upstream-update-plan.md).

## What this round brings

- **Protocol additions** (`varman-protocol/proto/control_plane.proto`):
  per-site failover policies (`SitePolicy`, `FailoverMode`), the global
  fail-open default, global and per-site cache ceilings
  (`GlobalCacheSettings`, `SiteCacheSettings`), site proxy-trust
  (`ProxyTrustConfig`), verified-bot fields (IP ranges + DNS verification),
  per-site managed-rule monitor overrides, security-event types, and agent
  sync timestamps. Upstream fields that collided with VarmanWAF's were
  renumbered (engine mode/virtual patches/OpenAPI keep 44-46;
  managed-rule monitors move to 47; bot fields to 7-9).
- **Agent model**: the rule cache now carries failover policies, cache
  settings, proxy trust and verified-bot ranges; site resolution follows
  primary → alternate domain; `effective_fail_open` resolves
  site policy → global default → local setting. Verified-bot plumbing
  (ranges + DNS flag) is in place for the WAF plugin batch.
- **Agent client**: TLS client configuration (custom CA file or inline PEM,
  injected in all-in-one mode), agent-token attachment on every RPC, config
  and policy sync timestamps in the heartbeat, randomized reconnect jitter,
  and `Set-Cookie`-aware header combining in access logs (newline-joined so
  cookie attributes with commas stay distinguishable).
- **Security events** carry an `event_type` (`waf` today) so the dashboard
  can deep-link to the protection that produced them.
- **Run mode boxing** (upstream shape): `Server`/`Agent`/`AllInOne` carry
  boxed configs, so later config growth cannot trip the large-variant lint.
