# VarmanWAF v1.1.3 - PHP2Shell virtual patch, body-aware patches

**Release date:** 2026-10-22 **Images:** `sovichetra/varmanwaf:1.1.3`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.3`

PHP2Shell (CVE-2026-109618 / CVE-2026-109619) is a pair of critical (CVSS 9.2)
PHP-core memory bugs that end in unauthenticated RCE and worker-memory
disclosure. Patching PHP is the only complete fix; this round ships the
edge-side bridge and the machinery that makes such a bridge trustworthy.

## What this round adds

- **Built-in virtual-patch templates.** The engine now ships curated SecLang
  sources (`varman_waf::virtual_patch_templates`) with two PHP2Shell patches:
  - `varman-php2shell` - for sites that accept uploads: blocks session
    upload-progress abuse (`PHP_SESSION_UPLOAD_PROGRESS`), multipart
    part-header floods (>100 part headers), file-control floods (>20 file
    controls), multipart without a declared `Content-Length`, and form
    field-name floods (>200 names). Rule ids `2026109618`-`2026109622`.
  - `varman-php2shell-no-uploads` - for sites that never take multipart:
    refuses every `multipart/form-data` request, the PHP advisory's own
    recommendation for such applications. Rule id `2026109617`.
  Both state their limits in their own text: a virtual patch reduces the
  input surface; the PHP update remains the complete fix.
- **`GET /api/v1/virtual-patch-templates`** exposes the catalogue; the site
  *Web Protection → Custom layers* panel gained a **Built-in virtual patch**
  picker that appends a template to the draft for review before Save.
- **Body-reading virtual patches now capture the body.** A patch whose rules
  target `REQUEST_BODY`, `ARGS`, `ARGS_POST*`, `FILES*`,
  `MULTIPART_PART_HEADERS`, `REQUEST_BODY_LENGTH` or `XML` makes the plugin
  capture request bodies for that site even when advanced mode is off.
  Previously such a rule compiled, validated and then silently never matched.
- **Docs**: new `docs/virtual-patches.md` (how patches work, the PHP2Shell
  templates, origin-side hardening from the advisories, honest limits -
  including that the edge has no response correlation), a `features.md`
  section, and a Khmer-guide section (៥.៤.៨).

## Verification at release

- Engine: 11 new tests - every template parses, each exploit shape (upload
  progress, part-header flood, file-control flood, chunked multipart,
  field-name flood) blocks, ordinary uploads / forms / JSON pass, rule ids
  are unique, `needs_body` classifies header-only vs body-reading rules.
- Control plane: the templates the API offers pass the same validation the
  settings endpoint applies.
- Console: tsc clean, eslint 0 errors, vitest passing.
- E2E: `run-e2e-virtual-patches.ps1` applies the PHP2Shell template to the
  test site, verifies the exploit shapes are blocked at the edge, verifies an
  ordinary upload still passes, then restores the previous posture - part of
  the full sweep.
- Live check on a production instance: the templates list renders in the
  panel; applying the patch and probing the exploit shapes returns the block
  page with the `php2shell` rule id in the security event.

## Honest limits (unchanged by this round)

- The edge evaluates requests only. Cloudflare's PHP2Shell rules pair request
  signals with the origin response ("full transaction detection"); VarmanWAF
  has no response-side correlation, so a variant under every threshold is not
  caught here.
- Body inspection is bounded (64 KiB plus the staged tail scan).
- A virtual patch never replaces updating the vulnerable runtime.
