# VarmanWAF v1.1.8 - One Protection mode, a simpler site workspace

**Release date:** 2026-10-23 **Images:** `sovichetra/varmanwaf:1.1.8`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.8`

This round fixes the source of the "rules say block but nothing blocks"
confusion: the site's enforcement mode had no control anywhere in the console.
The only mode switch changed each rule's mode, which the site gate then
overrode. There is now one control, in one place, with three states.

## What changed

### One Protection mode, in the site header

- A **Protection mode** control appears on every site tab: **Block**,
  **Monitor** or **Paused**. Block/Monitor write the site's WAF mode and make
  sure the site is active; Paused takes the site offline.
- The dialog states the consequence of each choice in plain language and
  records every finding either way.
- A site that follows a shared policy shows a **Managed by policy** badge;
  the dialog explains that the policy owns the mode and links to
  **Protection → Advanced** instead of offering a save that would be
  overridden.
- The separate pause/activate buttons were removed from the site header and
  the sites list: pausing is the Paused mode.

### A Rules page without a competing mode

- The bulk "apply this mode to every rule" card is gone.
- The posture banner reads the **effective** mode from the resolved
  configuration, not from the aggregate of per-rule modes.
- A rule's own mode is now labelled **Rule mode** and documented as an
  explicit override for that one rule; it never overrides the site mode.
- The callout at the top says exactly that, and the effective mode is the one
  shown.

### Simpler protection tabs

- **Overview · Rules · Flood protection · Advanced** replaces
  Overview / Rules / CC Protection / Policy tuning.
- The Overview starts with the operational modules, then the request path,
  then the optional shared policy - policies are no longer the first thing an
  operator sees.
- **Advanced** keeps paranoia, advanced mode, monitor-only categories,
  exclusions, shared policy and history. Its summary no longer presents a
  second mode chip.
- "Policies" is described as optional shared configuration; a site without a
  policy uses its own Protection mode and settings.

### Navigation and live-site links

- **Visit site** on the sites list opens the live site in a new tab; the list
  row and the domain open the site workspace.
- **The site domain in the site header is a link to the live site**, with an
  external-link icon. It uses HTTPS when the site has a certificate and HTTP
  for development hosts such as `*.local`.
- The site tabs put the security group (Protection, rate limiting, bot,
  access, API assets) immediately after Overview.
- On narrow widths the sites table hides the requests and added columns
  before it clips the action buttons; the Visit/Edit/Delete actions remain
  visible.

## Verification at release

- `npx tsc -b` clean; `npx eslint src` 0 errors; `npx vitest run` 34/34 (31 existing + 3 new live-site URL cases).
- Browser checks against the local control plane: the mode control was
  exercised through **Block → Paused → Monitor**; each state updated the site
  header, the paused banner and the API (`status`, `waf_enabled`, `mode`).
- The sites list Visit action opened `http://e2e.varman.local` with
  `_blank` + `noopener,noreferrer`; the detail domain link resolved to the
  same live URL.
- The Rules tab shows the effective **Monitoring** posture, the explanatory
  callout, the per-rule **Rule mode** column and no bulk mode card.
- The deployed binary reports `varman 1.1.8 (46848fb, tls=openssl)`.
- Full 45-script E2E sweep on the deployed local build: **45/45 passed**
  (the management-certificate script was the slowest at 481 s).

## Upgrading

```bash
cd ~/varmanwaf && docker compose pull
docker compose up -d --force-recreate varman
```

No database migration. Existing modes are preserved; opening a site now shows
the effective mode that was previously only visible in the API.
