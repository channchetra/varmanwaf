# VarmanWAF v1.2.3 — admin listener no longer freezes on an idle connection

**Release date:** 2026-10-27
**Images:** `sovichetra/varmanwaf:1.2.3`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.3`

Patch release for a control-plane availability bug on the 9080 listener.

## The bug

The dashboard listener accepts both HTTPS and cleartext HTTP on one socket.
Protocol detection previously ran **inline in `accept()`**: it awaited the
first byte, then the TLS handshake, before accepting the next connection.

A single client that opened a TCP connection to 9080 and sent nothing blocked
the entire listener. Every later request — including `/healthz`, the dashboard
and Docker's health probe — waited behind it. The container went unhealthy and
the dashboard stayed unreachable until the process was restarted. The IP
allowlist could not prevent this because the connection never reached HTTP.

This is also why the console could be wedged while the proxy on 80/443 kept
serving from cached configuration.

## The fix

- Protocol detection and TLS handshakes now run in bounded per-connection
  tasks; `accept()` never awaits a client byte.
- A client must send its first byte within **5 seconds** and finish the TLS
  handshake within **10 seconds**.
- At most **64** external handshakes run concurrently; excess connections are
  dropped instead of consuming unbounded tasks.
- **Loopback is reserved** so the container health probe and an SSH tunnel keep
  working even during an external slow-client burst.
- Added a regression test that holds an idle connection open and verifies a
  valid client is still accepted and answered.

## Verification

- `cargo test -p varman-control --lib tls::tests` → **25 passed**.
- The new regression test fails on the old inline `peek` path and passes with
  concurrent classification.
- Image smoke test: with an idle TCP connection held open, `/healthz` returns
  **200** instead of hanging; `/api/v1/version` reports `1.2.3`.
- This release also carries the 1.2.2 Google Sans console and refreshed docs.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.3
```

No migration and no configuration change. Roll back with the `1.2.2` tag.
