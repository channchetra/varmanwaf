# VarmanWAF v0.52.0 - Display & data timezone

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.52.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.52.0`

Deep check confirmed the gap: the console rendered every timestamp in the
browser's local zone, the server had no timezone setting, and report
date-only bounds were hard UTC. This round adds one setting that drives
both halves.

## What this round brings

- **Instance timezone** (`GET/PUT /settings/display`): an IANA name
  (e.g. `Asia/Phnom_Penh`), `UTC` by default, validated on write with
  `chrono-tz` (unknown zones are rejected with `400`). Any signed-in user
  reads it - the console needs it to render; administrators write it.
- **Display**: every absolute timestamp in the console (tables, detail
  rows, tooltips) renders in the configured zone; relative times are
  unchanged. The web applies it through the shared `Intl` formatters
  (`setDisplayTimeZone`), fetched once in the layout and again on save.
- **Data**: date-only report bounds are interpreted in the configured
  zone - `from=2026-10-14&to=2026-10-14` in `Asia/Phnom_Penh` covers
  `2026-10-13T17:00Z .. 2026-10-14T17:00Z` - and the **daily buckets**
  align to local days (`AT TIME ZONE`), including for scheduled reports.
  DST is handled through the real zone database (a midnight gap resolves
  to the earliest valid instant).
- **Settings** gains a **Display & timezone** section (after Appearance,
  matching the quick-nav): a timezone picker (the full IANA list via
  `Intl.supportedValuesOf`, curated fallback), read-only for non-admins.

## Verification at release

- `cargo fmt --check`, control tests **361 passed** (new: timezone
  resolution, UTC+7 boundary shift), clippy `-D warnings` clean; web
  `tsc`/vite/eslint clean, 20/20 unit tests, markers present.
- Live E2E (timezone script): default `UTC`; saving `Asia/Phnom_Penh`
  shifts a one-day report window to `17:00Z .. 17:00Z` exactly; an unknown
  zone is rejected (`400`); a viewer reads the setting (`200`) but cannot
  write it (`403`); the original value is restored.
- New dependency: `chrono-tz 0.10.4` (deliberate; DST-correct zones).
