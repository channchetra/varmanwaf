# VarmanWAF v0.41.0 - Batch 4c: the assistant becomes shared modules + a floating widget

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.41.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.41.0`

Batch 4 completes its dashboard work: the 876-line assistant monolith is
replaced by the upstream modular design, and the assistant gains its
floating widget. Web-only round - the AI server side is byte-identical to
upstream, so no endpoint changed.

## What this round brings

- **Shared assistant modules** (`web/src/components/assistant/`): the turn
  reducer (`turn.ts`), tool cards, message rendering (text nodes only -
  model output is never HTML), the conversation list, the chat panel and
  the mascot - plus `useAssistantChat` (all query/stream/selection state)
  and a small zustand widget store. The page and the widget now run the
  same code; two instances share the query cache by design.
- **The assistant page is a 113-line assembly** (header, conversation
  sidebar, mobile picker) instead of the monolith. **Fork divergence,
  recorded:** the page stays administrator-gated (the provider key is
  shared fleet-wide and the write tools can reach every site), where
  upstream opened it to every signed-in user - whose `GET /settings/ai`
  would 403 and dead-end in an ErrorState anyway.
- **Floating widget** (administrators only): a ball that slides in a right
  panel without an overlay, Escape closes it, and the panel is never
  unmounted - a running stream survives open/close. The header gains a
  Sparkle toggle next to the theme switch.
- **Page context**: each turn may carry a `page_path` hint derived from the
  route (`streamChatMessage` gained the optional argument; the server
  already accepted and validated it).
- **Slide-in-right animation** in `index.css` for the widget panel.
- **First assistant unit tests** (not upstream - ours): `reduceTurn`
  coverage (delta folding, tool call/result pairing, the `done` fallbacks,
  identity events) and the tool-payload helpers (`parseJson`,
  `formatJson`, `isToolError`). Web tests now run 15 across three files.

## Verification at release

- `npx tsc -b` and `npx vite build` clean; every assistant surface verified
  present in the built bundle (`Open AI assistant`, `Close assistant`,
  `Show history`/`Hide history`, the disabled copy, `page_path`,
  `animate-slide-in-right`).
- `npx vitest run`: 15/15. eslint: 0 errors; 3 new fast-refresh hints in
  `ToolCard.tsx` (the upstream file exports pure helpers next to the
  component) plus the 2 pre-existing router hints - kept verbatim so
  future upstream syncs stay mechanical.
- `cargo test -p varman-control` and clippy unchanged (no Rust edits this
  round).
- Live E2E (batch 4c script): administrator conversation CRUD round-trips
  (`POST` -> list -> detail -> `DELETE` -> 404); `GET /settings/ai` answers
  the settings view (no provider key stored, `enabled=False`); with no
  provider configured the turn endpoint refuses the request (409) before
  opening any stream; a viewer account gets 403 on `/settings/ai` - the
  gate the page mirrors - while the per-user conversation endpoints answer
  200 (the UI keeps the assistant admin-only regardless).
