# VarmanWAF v1.3.0 — TCP port forwarding for private services

**Release date:** 2026-10-28
**Images:** `sovichetra/varmanwaf:1.3.0`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.3.0`

Feature release: expose private TCP services (SSH, RDP, databases, internal
admin ports) through the edge without publishing the target itself.

## Also in this image (v1.2.12 batch)

- **Certificate-only changes reload the edge.** The watcher now compares a
  full-config `data_plane_hash` instead of the first site's bundle hash, so
  uploading or selecting a certificate for any site reloads the proxy without
  a restart. This fixed the `calendar.unity-workspace.com` 525 where a valid
  Cloudflare Origin CA certificate was not loaded.
- **Unauthenticated API-key prefix panic fixed** (ASCII-checked prefix).
- **Cross-tenant log read fixed** (explicit `site_id` now validates ownership).
- **ACME** scans every minute and backs off 5m → 15m → 30m → 1h → 6h per
  failed certificate/domain pair.

## What is new

- **Per-site TCP forwards.** Site → **Port forwarding** creates a listener on a
  published edge port and copies bytes to a private `host:port`.
- **Mandatory source allowlist.** Every forward requires at least one IP or
  CIDR. The agent checks the accepted peer before dialling the target and drops
  anything outside the list.
- **Port range 10000–10099.** The shipped compose publishes
  `10000-10099:10000-10099`. The API rejects a listen port outside the range
  and a listen port already used by another site.
- **Live reconciliation.** The agent diffs the control-plane list every two
  seconds: added/changed rules get a new listener, removed/disabled rules stop
  theirs. A bind failure is retried after 30 seconds.
- **Enable/disable without deleting.** Disabling a forward closes the listener
  immediately; enable it again to reopen.
- **Migration 066** creates `port_forwards` (FK to `sites`, unique listen port).

## Security notes

This is **raw TCP**. The target protocol's own encryption (SSH, RDP, TLS)
still applies; do not expose a plaintext protocol over the internet. Keep the
allowed source list as narrow as possible and prefer a VPN/zero-trust layer.
The target cannot be the WAF's own listener ports (80/443/9080/9090), which
would create a loop.

Deployment requirements:

- Publish the same range in Docker/host firewall (the compose file does).
- Open the range in the host firewall.
- `port-forwards` is a per-site page under the site navigation.

## Verification

- Control-plane tests: port range, allowlist parsing, target validation,
  migration count/order.
- Agent tests: allowlist parsing (CIDR + bare IP), rule-diff detection.
- Console build and route.
- After deployment: create a temporary forward to a known private service,
  connect from an allowed source, then delete it.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.3.0
```

The migration runs automatically. Existing deployments must add the port range
to their compose/firewall before using a forward. v1.3.0 includes everything in
v1.2.12 (certificate reload, upstream security batch 1, ACME backoff).
