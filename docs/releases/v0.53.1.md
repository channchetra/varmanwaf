# VarmanWAF v0.53.1 - Honest ASN surfacing (found by the new analysis tool)

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.53.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.53.1`

v0.53.0 was tagged in git but its image was superseded before publication:
the first live run of the new IP-analysis tool surfaced a real defect in the
same area, and shipping the fix inside the release is worth more than
shipping a clean-looking artifact. Operators get the fix in the **0.53.1**
image.

## What the tool found

The embedded geo database (`tor-geoip`, `new_embedded`) **carries country
data only** - it passes `None` for the ASN slice of its range map. The
plugin's geo `blocked_asns` check has therefore been a **silent no-op**: the
lookup always returns `None`, so the list could never match, while the UI
and API accepted and displayed it as if it were enforced.

## What this round changes

- **Access control -> Geo, ASN card**: a notice appears whenever the list is
  non-empty - the entries are stored but do not match, country rules are
  unaffected.
- **IP analysis**: the ASN row already reports `unknown` (matching the edge
  exactly); the limitations list now states *why*: the embedded database
  carries country data only, so ASN lookups and ASN block lists cannot
  match.
- **Data plane**: the plugin logs one warning per compiled site when
  `blocked_asns` is configured, instead of silently skipping the check.
- No enforcement semantics change: the check stays in place so a future ASN
  database lights it up.

- Live E2E (country-access script): analysis on a documentation range is
