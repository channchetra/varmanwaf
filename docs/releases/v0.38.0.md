# VarmanWAF v0.38.0 - Upstream batch 3c: branded edge pages, storable clearance

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.38.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.38.0`

The last sub-batch of upstream batch 3: every edge-generated response now
looks like the product that issued it, and challenges work on plain HTTP.

## What this round brings

- **Branded short-circuit pages** (block 403, basic auth 401, paused 503,
  rate limit 429): the same `PW_STYLE` partial the error-page engine uses -
  the VarmanWAF orange accent, light/dark aware, icon + code label + heading
  + message + a details block (Request ID, Reason, Time) - with a
  "Protected by **VarmanWAF**" footer. Reasons are **HTML-escaped**, so a
  rule description or attacker-influenced text can never inject markup into
  the page.
- **Edge provenance headers** on every edge-generated response:
  `Server: varmanwaf` and `x-varmanwaf-mitigated: block|challenge`
  (Cloudflare's `cf-mitigated` idea). A visitor - or the site owner
  debugging a report - sees from the headers alone that security answered.
- **Storable clearance on HTTP**: the clearance cookie's `Secure` attribute
  is now attached **only** when the verify request arrived over TLS.
  Browsers refuse to store `Secure` cookies on plain HTTP pages, which made
  challenges unsolvable there; the challenge engine threads the request's
  TLS state through `verify_solution` and `cookie_attributes`.
- **Open-redirect guard**: the post-verification redirect target comes from
  the request line, so it is now constrained to same-origin paths
  (absolute URLs, `//host` and backslash tricks fall back to `/`) and
  escaped into the inline script - closing a reflected-injection edge.
- The challenge page response itself carries the same edge headers, so a
  challenged request is identifiable too.

## Verification at release

- New plugin tests: the block page is branded (accent, product footer,
  request id) and stamped (`server`, `x-varmanwaf-mitigated`); reasons are
  escaped; paused/rate-limit/basic-auth pages are branded with their
  headers (`retry-after`, `www-authenticate`, mitigation); the redirect
  guard keeps same-origin paths only. The challenge crate's cookie tests
  cover the `Secure`/non-`Secure` pair, and the existing WAF test now
  asserts the branded body.
- `cargo test --workspace` green (plugin 193, challenge 40); clippy
  `-D warnings` clean.
- Live E2E: a blocked request returns the branded page with
  `server: varmanwaf` and `x-varmanwaf-mitigated: block`; a benign request
  is unaffected; cleanup as usual.
