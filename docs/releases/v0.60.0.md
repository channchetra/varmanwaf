# VarmanWAF v0.60.0 - Upstream exclusion import (SecLang)

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.60.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.60.0`

The deferred half of exclusion packages: importing the upstream CRS
rule-exclusion plugins (WordPress, Nextcloud, Drupal, …) from GitHub. The
recon changed the design twice and both changes are in the release notes
because they matter.

## What the live sources actually look like

The CRS plugins are **full SecLang rulesets**, not bare exclusion
directives: the WordPress plugin carries ~1,200 of its own rules whose
actions include **`ctl:ruleRemoveTargetById`** (423 uses),
`ctl:ruleRemoveTargetByTag` (112) and `ctl:ruleRemoveById` (19) - the
inline exclusion controls. Standalone `SecRuleUpdateTargetById` lines: 0.

## What this round brings

- **`ctl:ruleRemoveTargetById` in the SecLang evaluator** (it was the one
  control the plugins need and the engine lacked; unknown ctl ops are
  refused at parse time, so before this round the imports could not even
  be stored). The by-tag variant already existed; the by-id variant mirrors
  it: `(rule id, target)` entries applied per transaction, consulted when a
  rule's targets are filtered.
- **Import API** (`POST /exclusion-packages/import`, admin): fetches an
  https source (2 MiB cap), **refuses anything that does not parse as
  SecLang**, and stores it as a `seclang` package with a report: directives,
  the file's own rules, exclusion controls, standalone retargets/removals,
  the addressed rule ids, and the version sniffed from a comment
  (`v1.7.1` and `Plugin version: 1.2.0` both parse).
- **Attach = compiled into the site's virtual patches**, after the CRS
  import, where the evaluator applies the controls natively. SecLang
  packages are site-wide by nature, so a binding must use the root prefix
  (enforced with a clear message) - and the round fixes the root-prefix
  normalisation that used to collapse `/` into an empty string.
- **Console**: an **Import upstream exclusions** card (URL, import, report)
  and SecLang packages rendered with their source link, report and a
  site-wide attach; non-builtin packages can be removed
  (`DELETE /exclusion-packages/{key}`).

- `cargo fmt --check` exit 0; control tests **378** (report classification
  incl. inline ctl controls, URL-to-key derivation, root-prefix
  normalisation); engine **495**; plugin **200**; agent **42**; clippy
  `-D warnings` clean; web tsc/eslint/vite clean, 20/20 unit tests.
- Live E2E (import script): the real WordPress plugin imports from GitHub
  (`rules` in the thousands, hundreds of exclusion controls, version
  `1.2.0`); attaching at a non-root prefix is refused (`400`); attaching at
  `/` pushes the bundle and the site keeps serving with **no compile
  failure** in the edge log; the binding and package are removed afterwards.

## Honest scope

The imported rules join the site's SecLang layer; they act on the CRS
rules that layer carries (import a CRS ruleset to give them targets). The
`entries`-kind packages (v0.56-v0.59) remain the precise, path-scoped
mechanism for managed and custom rules; the two kinds are labelled in the
console so the difference is visible, not implied.
