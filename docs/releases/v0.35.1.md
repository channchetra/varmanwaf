# VarmanWAF v0.35.1 - Fix: manual IP-group creation after the selector column

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.35.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.35.1`

A one-bug fix on top of v0.35.0 (upstream batch 3a). The verified-bots work
is unchanged; this release carries the batch because v0.35.0 failed its E2E
before anything was published.

## The bug

`POST /api/v1/ip-groups` answered **500** with

```
null value in column "source_selector" of relation "ip_groups"
violates not-null constraint
```

The `source_selector` column (added in v0.33.0, migration 000057) is
`NOT NULL DEFAULT ''`, but the model typed it `Option<String>` and the
insert path used `Set(None)` - SeaORM then sends an explicit `NULL` in the
INSERT, overriding the column default. Any manual group creation (and any
catalog import of a source *without* a selector) hit it. The v0.33.0 E2E
never exercised it because every import it made had a non-empty selector.

## The fix

- The model now mirrors the column: `source_selector: String` (empty means
  "auto-detect"), so inserts must supply a value - enforced at compile time.
- `api/ip_groups.rs`: create/update store `validate_selector(..)?
  .unwrap_or_default()`; the sync path reads the field directly.
- `api/ip_lists.rs`: imports store the plan's selector verbatim and the
  dedupe query is now a plain string match (no NULL branch).
- `defaults.rs` and the two `grpc/config.rs` fixtures follow the new shape.
- New unit tests: selector normalisation (absent/blank collapse to auto,
  trimming, 500-char cap, control characters rejected) and range validation.

## Verification

- `cargo test --workspace` green; clippy `-D warnings` clean; `tsc -b &&
  vite build` clean.
- Live E2E (verified bots, batch 3a): a spoofed Googlebot user agent passes
  on the whitelist alone; DNS verification refutes it (403) while a browser
  passes; disabling the whitelist but verifying by IP range makes it pass
  again; with both off it is denied; the site configuration is restored -
  and manual IP-group creation works again.
