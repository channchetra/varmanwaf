# VarmanWAF v1.4.4 — NUL sanitisation covers stored bodies

**Release date:** 2026-11-27
**Images:** `sovichetra/varmanwaf:1.4.4`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.4.4`

Hotfix for 1.4.3. The scalar log fields were sanitised, but the captured
request/response bodies were not: `body_text()` decoded them with
`String::from_utf8_lossy`, which preserves `U+0000`. A POST body containing a
NUL byte therefore still made PostgreSQL reject the whole batch, and the agent
retried it until a restart.

## Fix

`body_text()` now replaces NUL with `U+FFFD`, the same replacement used by
`optional()` and `truncate()`. The regression test covers a body of `a\0b`,
an empty body, and invalid UTF-8 followed by a NUL.

`varman-control/src/grpc/control_plane.rs`.

## Verification

- `varman-control`: 423 tests, clippy `-D warnings` clean.
- Production: a POST with a raw NUL body through a temporary site stored the
  row with `U+FFFD` and produced no `invalid byte sequence` error.

Everything from 1.4.3 is included: gRPC TLS rotation without restarts, the
renewal watchdog, and the stream-inspection corrections.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.4.4
```

No migration is required.
