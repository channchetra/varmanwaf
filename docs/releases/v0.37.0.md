# VarmanWAF v0.37.0 - Upstream batch 3b: request-body staging

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.37.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.37.0`

The remainder of an over-window request body is now **withheld, scanned and
only then forwarded** - upstream PingWAF's staging model, adapted to this
fork's early-read pipeline.

## What this round brings

- **`stage_chunk` state machine** (ported from upstream, pure and
  unit-tested): `Withhold` buffers a chunk and replaces the outgoing body
  with an **empty chunk** - never `None`, which would signal end-of-body
  and truncate the upstream request; `Flush` fires once when the cap is
  crossed, returning everything staged for scanning; `PassThrough` leaves
  the stream alone past the cap.
- **Staged remainder**: when the early read stops before the end of a body
  (a body larger than the 64 KiB replay window) and the site inspects
  bodies, the body filter now withholds every chunk up to the inspection
  cap, scans the staged bytes with the same native pipeline the tail scan
  uses, and only then hands them upstream. A payload in the first 64 KiB
  of the remainder therefore never reaches the origin - previously it was
  only seen by the tail scan *while* streaming.
- **Past the cap**: the rest flows untouched (bounded memory), exactly like
  the tail scan before it; the site's explicit `reject` size policy still
  refuses over-cap bodies outright when configured.
- **Sweep**: staged entries abandoned mid-exchange (a client that vanished
  while sending, or a request answered before its body filter ran) are
  dropped by the periodic access-log sweep on the same TTL, so withheld
  bytes cannot linger.

## Honest scope notes

- Upstream additionally re-runs the **full native engine verdict** on the
  completed body; this fork keeps its documented divergence - the engine
  runs on the early-read prefix (or the staged flush) and the remainder is
  covered by the stream scanner, which is the same pipeline. The port
  changes *when* the remainder's bytes are scanned (before forwarding),
  which is the property that matters.
- The `reject` body policy remains the default; staging applies to sites
  that inspect bodies without the reject policy.

## Verification at release

- New unit test for the state machine (withhold at and below the cap, one
  flush exactly once at the crossing, passthrough afterwards, an empty
  end-of-stream call that must not flush on its own).
- `cargo test --workspace` green; clippy `-D warnings` clean.
- Live E2E: a 96 KiB POST whose trailing bytes carry an XSS signature is
  answered **403** (staged scan before the origin), a benign 96 KiB POST
  passes **200** with the body delivered intact, a below-window body with
  the same payload is still blocked, and the site configuration is
  restored afterwards.
