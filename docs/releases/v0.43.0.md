# VarmanWAF v0.43.0 - Configuration history in the console: inspect, and roll back with evidence

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.43.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.43.0`

**Superseded by [v0.43.1](v0.43.1.md)**: the release E2E found that a
rollback recorded two versions (mismatched fingerprints between the
rollback path and the push path); no images were published for v0.43.0,
and v0.43.1 carries this batch.

Configuration versioning has existed server-side since the upstream delta
was absorbed - every settings change records a restorable snapshot, the
CLI (`varman config history | show | rollback`) reads it, and the API
serves it - but the dashboard could not see any of it. This round gives it
its console surface, and the `configVersions` client ported in v0.41.1 its
first consumer.

## What this round brings

- **Configuration history page** (`/config-history`, "Config history" in
  the sidebar): every recorded version across the deployment-wide scope
  and each site, newest first, with the scope, source (API / CLI /
  Rollback), operator, timestamp and snapshot size. Scope filter (all /
  global / one site), manual refresh, 100-row page.
- **Detail view per version**: scope, source, actor, timestamp, config
  hash and the snapshot's per-table row counts, sorted by size - the
  evidence behind the restore, not just a version number.
- **Rollback with honest copy**: the confirmation states exactly what
  happens - the scope's tables are replaced with that snapshot, the
  rollback is recorded as a new version itself, and the restored
  configuration is pushed to the agents immediately - and the success
  toast reports both version numbers. Administrator-only, mirroring the
  server routes (non-admins get the overview and an explicit note, not
  403s).
- **Type fix while wiring the first consumer**: the ported
  `ConfigVersionDetail` claimed `site_domain`, but the server's detail
  route returns the raw model (no resolved domain). The type now says so,
  and the page resolves the site name from the sites list.
- **Tests**: `lib/configHistory.ts` helpers (summary totals, sorted rows
  with optional trim, scope label fallbacks) - web suite now 18 across
  four files.

## Verification at release

- `npx tsc -b`, `npx vite build` and eslint clean; bundle markers for the
  page, its overview box and the rollback dialog.
- Live E2E (config-history script): the newest site-scope version is
  listed, its detail carries the snapshot (`schema`, per-table counts) and
  - as the type fix documents - **no** `site_domain`; a rollback of that
  version reports `restored_version` / `new_version` / `scope` and appears
  in the list as a new version with `source=rollback` attributed to the
  operator; the site's effective config still resolves; a viewer account
  gets 403 on both the list and the rollback route. The rollback target is
  the newest version of the E2E site, whose snapshot equals the current
  state, so the restore is a verified no-op write - the safest possible
  live exercise of the path.
- `cargo fmt --check`, workspace tests and clippy untouched (web-only
  round; no Rust edits).
