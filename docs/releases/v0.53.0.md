# VarmanWAF v0.53.0 - Country access: geo monitor + client IP analysis

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.53.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.53.0`

The first Tiyi port from `tiyi-analysis/api-assets-and-country-access.md`:
country rules become observable, and the "why is this IP treated this way?"
question gets an answer. Patterns only - nothing is copied from Tiyi.

## What this round brings

- **Geo monitor action** (the `country_monitor` pattern): the geo policy's
  action list gains `log` - matches are recorded with the **monitor**
  action and the request continues, nothing is enforced. It flows through
  the existing action pipeline (`log` -> proto `WAF_ACTION_LOG` -> the
  plugin's `monitor` flag) and reuses the observation-mode downgrade path
  in the request handler, so there is one recording mechanism, not two.
- **Client IP analysis** (`GET /sites/{id}/ip-analysis?ip=...`, admins):
  resolves an address against **the same configuration the edge bundle is
  compiled from** - the site's IP rules in priority order, the enabled IP
  groups that apply to the site, then the geo policy - using the **same
  embedded geo database** the edge resolves with. The answer names the
  deciding layer, the matched rule/group, the country/ASN, the geo reason,
  and an explicit **limitations** list (policy-layer IP rules are not
  simulated; live state - challenges, clearance, connection tracking - is
  not visible; observation mode is called out when on).
- **Access control -> Geo tab** gains the analysis card (input + verdict
  panel) and the action picker gains **Monitor (record only)** with its
  own hint.

## Verification at release

- `cargo fmt --check` exit 0; control tests **364 passed** (new: range and
  ASN parsing, geo semantics incl. allow-list and unknown-country cases,
  the monitor action's proto mapping); plugin tests **194 passed**,
  including a new data-plane test that a monitor geo rule **continues the
  request and emits the event with `monitor`**; clippy `-D warnings` clean;
  web `tsc`/eslint/vite clean, 20/20 unit tests.
- Live E2E (country-access script): analysis of a public address resolves
  country/ASN and passes; a matching IP rule flips the verdict to block and
  names the rule; with the rule gone and the geo action set to monitor the
  verdict is **monitor** with the geo reason; invalid input is rejected
  (`400`) and a viewer is refused (`403`); **through the edge**, a monitor
  geo rule records a `monitor` security event while the request is served
  (`200`), and switching the action to `block` produces the `403` - the
  monitor path is real, not a label. State is restored and the probe IP is
  unblocked afterwards.
