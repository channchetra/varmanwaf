# VarmanWAF v1.2.8 — origin health checks you can see and trigger

**Release date:** 2026-10-27
**Images:** `sovichetra/varmanwaf:1.2.8`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.8`

Feature release for origin operations, plus the Renew button wrapping fix.

## Origin health checks

The edge already supported active HTTP health checks per origin pool, but the
console did not expose them and never showed a node’s health. The Origin page
now has both.

- **Per-pool active check settings:** enable the probe, set the path
  (`/health`), interval (5–3600 s), timeout (100–30000 ms) and the
  failure/success thresholds. The edge takes a failing node out of rotation
  and puts it back when it recovers.
- **Test now:** probes every node in the pool immediately and opens a result
  window with the HTTP status, latency and the connection/TLS error for each
  node.
- **Health column:** each node keeps the last manual result:
  **Reachable**, **Reachable · 5xx** or **Unreachable**. The result is stored
  in `site_upstreams.health_status`.
- **Pool summary:** the card shows the active check path and interval, or
  “No active check”.

### What “Test now” actually checks

The probe runs from the **control-plane process**. In all-in-one mode that is
the WAF host, so it answers “can the WAF reach this origin?”. In a split
deployment it tests the control-plane network path; an edge node on a
different network can still differ. The origin sees the site’s public `Host`
header.

The probe uses plain HTTP or TLS exactly as the pool is configured: SNI for an
HTTPS pool, and the pool’s verification setting (a self-signed origin with
verification off is accepted; verification on reports the certificate error).
A 5xx response marks the node **degraded** rather than unreachable, because
the network path worked.

## Renew button

“Renew now” in the global SSL/TLS table wrapped onto a second line when the
action column was tight. Buttons now use `whitespace-nowrap` and the action
column is wider, so the label stays on one line.

## Verification

- `cargo test -p varman-control --lib api::sites` → **10 passed**, including
  origin address parsing for host:port, pasted schemes and IPv6 literals.
- `npm run build` → console bundle builds.
- The probe is covered by the API tests and is exercised against the live
  origins after deployment.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.8
```

No migration and no configuration change. Existing pools keep their stored
health-check settings; the Origin page now shows them.
