# VarmanWAF v1.2.6 — watch certificate issuance in real time

**Release date:** 2026-10-27
**Images:** `sovichetra/varmanwaf:1.2.6`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.6`

Feature release for certificate operations. Applying for an ACME certificate
or clicking **Renew now** used to return a toast and a `pending` row; the raw
progress was only visible in the application log. The SSL/TLS surfaces now
open a live issuance log that follows the order while it runs.

## What is new

- **Live log after submit or renew.** Applying for an ACME certificate opens
  the log automatically (the dialog has an “Open the live log after
  submitting” switch, on by default). **Renew now** always opens it.
- **View log on every certificate row.** The terminal button in the
  certificates table opens the same window at any time, including for
  uploaded certificates that already have an event history.
- **Real-time tail.** The dialog appends new `certificate_events` rows every
  1.5 seconds and refreshes the certificate status every 2.5 seconds. It shows
  the event type, timestamp and raw ACME line, with the certificate status
  (issuing / active / failed) and a live/paused indicator.
- **Pause, copy, download, jump to latest.** The transcript can be paused
  while reading, copied to the clipboard, downloaded as a `.log`, and the view
  follows the newest line unless the operator scrolls up.
- **Per-site and global.** The live log is available from both **SSL/TLS**
  (global certificate table) and a site's **SSL/TLS** page.
- **Incremental API.** `GET /api/v1/certificates/{id}/events` now accepts
  `since=<RFC 3339>` and `order=asc`, so each poll returns only new rows
  instead of re-reading the whole history. The existing paginated log tab and
  its newest-first order are unchanged.

## What the log shows

- `renewal_requested` when the renewal is queued;
- `acme_raw` lines from the edge: order creation, authorization status,
  challenge token served, validation and “renew certificate success”;
- `issuance_failed` with the stale-order reason;
- `created`, `renewed`, `deleted` and management-certificate events.

A queued renewal is picked up at the next ACME window (the task checks every
minute and starts orders on every tenth cycle, about 10 minutes), so the log
can legitimately show “No log lines yet” for a few minutes. The dialog says so
rather than looking stuck.

## Verification

- `cargo test -p varman-control --lib` → **412 passed**, including new tests
  for RFC 3339 parsing and ascending order on the live query.
- `npm run build` → console bundle builds.
- The event API keeps its existing default ordering and pagination, so the
  SSL/TLS log tab and other callers are unaffected.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.6
```

No migration and no configuration change. The live log reads the existing
`certificate_events` table.
