# VarmanWAF v0.33.0 - Clarity, a real search, and a catalog of real IP lists

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.33.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.33.0`

A UI/UX round modelled on the studied product's protection panel, plus two
concrete gaps this deployment had: the header search box was a stub, and IP
lists had no way to pull the public country/bot/VPN data.

## What this round brings

- **Protection Overview** - the site's Web Protection tab now opens on an
  **Overview** that states what is actually in force:
  - an **effective policy banner** (policy name + revision, "fully follows
    policy" vs "N site overrides", engine / mode / paranoia / advanced /
    engine-mode / effective-rule stats, and the published-vs-applied badge
    from the same apply-status the Policy tab uses),
  - the **effective request path** in runtime order - IP & country access,
    bot protection, rate limits, rules & CRS, CC/under-attack - each stage
    card linking to the page that owns it,
  - a short **short-circuit note** (an IP/geo or bot denial answers before
    rate limits; rate limits before the engine; the engine's mode caps
    everything),
  - **protection modules** cards with "site override / from policy / site
    settings" chips, so the policy-vs-site question is answered before any
    setting is edited.
- **A search that works.** The header box (and ⌘/Ctrl+K) now opens a search
  palette over what the API actually exposes: pages, sites, policies, IP
  lists, CRS rulesets and alert rules, with keyboard navigation and grouped
  results. No hidden index: an entry shown is one the backend has.
- **The policy editor breathes.** The policy name/revision/used-by row and
  the History/Test actions moved into their own header row, the layer tabs
  got larger hit areas, a banner states what saving here means ("published
  here, applied on the next sync - use Test first"), and the save footer is
  separated with room to click.
- **IP list catalog** (`/api/v1/ip-lists/*`, "Browse lists" on the IP lists
  page and on every site's IP access tab):
  - **Countries** - ipverse `country-ip-blocks` (compact, RIR delegations)
    and `geo-ip-blocks` (detailed, registration records), both IPv4+IPv6,
    CC0. Choose the granularity at import time.
  - **Crawlers & uptime probes** - ipverse `bot-ip-blocks` (CC0), read live
    so the console shows the source's own service names, prefix counts and
    the `ip_list_authoritative` flag; lists that are only a prefilter
    (shared with non-crawler traffic) are labelled as such. "All crawlers" /
    "All probes" import whole files.
  - **VPN & datacenters** - X4BNet `lists_vpn` (MIT, IPv4 only, stated in
    the catalog entry).
  - **ASN** - ipverse `as-ip-blocks` (CC0) per autonomous system.
  - **Custom URL** - plain text or JSON, with an optional **JSON selector**
    (new `ip_groups.source_selector`, migration 000057) so one document can
    feed many lists (`prefixes.ipv4,prefixes.ipv6`, `services.Googlebot.*`).
  - Imports are ordinary **IP group subscriptions**: daily refresh through
    the existing scheduler, a dedupe guard (409 names the existing group),
    and an honest first fetch - the group keeps the real `last_sync_error`
    when the source (or a selector) fails instead of pretending success.
- **Parser hardening**: the subscription parser also understands the
  ipverse `prefixes` and `services` JSON shapes by default, deduplicates
  ranges, and a selector that matches nothing is an error - a renamed
  upstream key surfaces as a sync failure, never as an empty list.

## Verification at release

- New unit tests: the 249-country table (complete, unique, spot-checked),
  catalog id resolution (countries/variants/ASN/VPN/bot services, invalid
  ids rejected), the ipverse country + bot JSON shapes, selector behaviour
  (match, miss, selector-on-text), and selector normalisation in the group
  API.
- `cargo test --workspace` green; clippy `-D warnings` clean; `tsc -b &&
  vite build` clean.
- Live E2E against the real sources: the catalog reports 249 countries +
  VPN + live bot services (with counts and the authoritative flag);
  importing `country:kh`, `bot:Googlebot` and `asn:15169` fetches real
  ranges through the API; a second import of the same source is refused
  with 409; a selector that matches nothing keeps the group with the error
  recorded; the imported group binds to a site IP rule; everything is
  cleaned up.
