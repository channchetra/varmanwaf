# VarmanWAF v0.41.1 - Batch 5 closed: the feature branches were already absorbed

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.41.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.41.1`

Batch 5 was scoped as "port the upstream feature branches
`feature/config-versioning-and-notifications` and
`feature/per-site-failover` once main is synced". Reconnaissance closed it
differently - and honestly:

## The finding

Both branch tips are **ancestors of `aa597371`**, the upstream commit whose
net delta batches 1-4 already synced. The branches were merged upstream
*before* that delta - the plan's "not in main's delta yet" note predated the
merge - so their features have been arriving with the delta all along.
Verified against the live fork:

- **Config version history**: server routes (`GET /config-versions`,
  `GET /config-versions/{id}`, `POST /config-versions/{id}/rollback`), the
  model, the migration (renumbered to `m20240101_000045_config_versions`
  during the batch-2b port) and the CLI (`varman config history | show |
  rollback`) are present - and have been recording: the live database
  holds **50 versions**.
- **Notifications**: server + Alerts page + the batch-4b Notifications page.
- **Per-site failover**: server + the batch-4b FailoverPanel in site
  settings.

The only file from either branch missing here was
`web/src/api/configVersions.ts` - an API client that **nothing consumes
upstream either** (the barrel re-exports it; no config-history UI exists in
either tree). This release ports it verbatim, with a doc comment naming the
admin-only gating and rollback semantics, and exports it from our barrel so
future upstream syncs stay mechanical.

## Verification at release

- `npx tsc -b` and `npx vite build` clean; the client is exported from
  `@/api` (type-checked, no runtime surface yet).
- Live E2E (batch 5 script): `GET /config-versions` answers newest-first
  (50 rows, `global` scope and site rows with their `site_domain`);
  `GET /config-versions/{id}` returns the snapshot document (`schema`,
  `tables` counts); the `site_id=global` filter and a site-UUID filter both
  select their scope; a viewer account gets 403 on both reads and on the
  rollback route - the administrative gate holds. No rollback was executed:
  it restores state and is not reversible by an E2E.
- Rust untouched: no rebuild of server logic, the binary changes only
  through the embedded web bundle.
