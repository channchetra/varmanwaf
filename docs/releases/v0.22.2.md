# VarmanWAF v0.22.2 — upstream sync round 2b-1 (control-plane schema groundwork)

**Release date:** 2026-10-13 · **Images:** `sovichetra/varmanwaf:0.22.2`,
`sovichetra/varmanwaf:latest` · **Tag:** `v0.22.2`

Second half of the agent/control-plane round, first slice: the control-plane
**database schema groundwork** for the upstream v0.25.10 features. Migration
only — no API or enforcement behaviour changes yet; the APIs land in 2b-2.

## What this round brings

- **20 upstream migrations**, renumbered to continue our sequence
  (`000033`–`000052`; upstream shipped them as `000031`–`000050`, colliding
  with our engine-mode and virtual-patch migrations). They add, all
  additive-safe (no bare `NOT NULL`, no column collisions with our schema):
  * `waf_settings`: `monitor_managed_rules`, `waf_enabled`, `mode`,
    `paranoia_level`;
  * `security_events`: `event_type`;
  * `sites`: proxy-trust columns, trusted-proxy ranges/group ids, cache file
    size cap, failover policy;
  * `users`: account controls and `token_version`;
  * `agents`: config/policy sync timestamps;
  * new tables: `instance_settings`, `config_versions`, `notifications`,
    `login_histories`, `cache_settings`;
  * `certificates`: failure reason; upstream pools: health-check settings.
- **5 new models** (`cache_settings`, `config_versions`, `instance_settings`,
  `login_histories`, `notifications`) registered in `models/mod.rs`.

## Verification at release

- `cargo check --workspace --all-targets` clean; control-plane 215 tests
  (the migrator ordering test now asserts 52 migrations); full sweep green;
  clippy `-D warnings` clean.
- Live deploy: migrations apply on the running database at start-up (schema
  spot-check), control-plane health, agent registration, WAF probes
  unchanged.
