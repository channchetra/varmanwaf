# VarmanWAF v1.1.9 - Accessible by keyboard, readable in both themes

**Release date:** 2026-10-23 **Images:** `sovichetra/varmanwaf:1.1.9`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.9`

This round is the follow-up to the Impeccable audit of the console. It does not
change the WAF model, the API or the site workflow. It removes the places where
the console was hard to read or operate without a mouse, makes charts and
topology follow the theme, and stops shipping every page in the first
JavaScript download.

## What changed

### Contrast that survives both themes

- **Ember is a fill, not a text color.** Primary buttons now use dark ink on
  the ember fill (6.53:1; 5.46:1 on the light hover fill). Ember labels, icons
  and active navigation use a new `brand-ink` token (`#a34700` light /
  `#ffb066` dark), which measures 6.07:1 on the light canvas and 5.44:1 on the
  soft tint; the dark values are 9.36:1 and 6.57:1.
- **Danger and warning text have ink variants.** Danger text uses `#b83c2c`
  light / `#ff6340` dark; warning text uses `#805b09` light / `#ffc53d` dark.
  Filled destructive buttons use the darker Danger Strong fill with white text
  (5.18:1 / 5.64:1) and darken on hover.
- **Placeholders are readable.** Input hints use a dedicated token
  (`#767676` light / `#9a9a9a` dark, 4.54:1 / 5.10:1) instead of a translucent
  muted color.
- Card metadata and topology subtitles use the full muted token instead of
  70–80% opacity, which measured 4.04:1 in dark.
- The theme-aware switch uses `brand-ink` for its on track so its boundary is
  visible in both themes.
- The login brand panel is graphite with white text (16.9:1) instead of white
  text on a full ember surface. The assistant user bubble also uses dark ink on
  ember.

### Keyboard, focus and assistive technology

- **Sortable table headers are real buttons.** Tab reaches the header, Enter or
  Space changes the order, and the `<th>` exposes `aria-sort="ascending"`,
  `"descending"` or `"none"`. Click-anywhere `<th>` handlers are gone.
- **Dialogs behave like modal dialogs.** Focus moves to the panel on open, Tab
  is trapped inside, the app root becomes `inert`, Escape closes, and focus
  returns to the control that opened it. The dialog title and description are
  linked with `aria-labelledby` / `aria-describedby`.
- **A skip link** is the first stop from a page start and targets `main#main`.
- The login screen now exposes a `main` landmark, and its password reveal
  control has a 24 px target.
- The account menu now has an accessible name plus `aria-haspopup` and
  `aria-expanded`.
- The closed AI assistant panel is `inert`, so its controls are no longer
  focusable behind `aria-hidden`.
- Card headings are `h2` under the page `h1`, removing the skipped heading
  level on dashboard and settings cards.
- Mobile buttons and icon controls have a 44 px minimum target; the mobile
  sidebar matches.

### Motion, charts and loading

- **Reduced motion is targeted.** The old global 0.001 ms rule erased useful
  state feedback. It now removes decorative animation and transform
  transitions while keeping 150 ms color, border and opacity feedback.
- **Charts and topology follow the theme.** Recharts series and gradients use a
  resolved-theme palette (`chartPalette.ts`), and topology nodes, edges and
  minimap chrome use theme tokens instead of light-mode hex values.
- **Routes load on demand.** Page components are `React.lazy` chunks behind the
  shell's Suspense boundary. The entry chunk fell from about 1.25 MB to 86 kB;
  the dashboard, traffic, topology and settings payloads load when their route
  is opened.

### Dashboard correctness

- Top-rule rows are keyed by **rule id + action**. The analytics API legitimately
  returns the same managed rule (for example `VARMAN-1020`) once as `monitor`
  and once as `block`; the old key collided in React and could omit one of those
  rows.

### Design-system record

- `web/DESIGN.md` and `web/.impeccable/design.json` now document the new
  contrast tokens, the switch treatment, the keyboard/focus rules and the
  reduced-motion behavior.
- The Impeccable detector reports **0 findings**. The two generated email
  error-page type sizes (22 px / 96 px) carry a narrow inline waiver because
  they are emailed artifacts, not console UI.

  `run-e2e-ui-fixes.ps1` and `run-e2e-topology.ps1`.

## Upgrading

```bash
cd ~/varmanwaf && docker compose pull
docker compose up -d --force-recreate varman
```

No database migration and no API change. Existing modes, rules, policies and
logs are preserved.
