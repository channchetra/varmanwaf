# VarmanWAF v0.29.0 - Policy & Rule Control Plane, round 6 (P6: the remaining layers)

**Release date:** 2026-10-14 • **Images:** `sovichetra/varmanwaf:0.29.0`,
`sovichetra/varmanwaf:latest` • **Tag:** `v0.29.0`

The final policy round: the remaining per-site features move under the
policy model. A policy now carries **nine layer kinds**, shared by every
assigned site, with the site overlay used only where a site genuinely
differs.

## What this round brings

- **Five new layer kinds** (validated against the same contracts as the
  per-site APIs):
  - `virtual_patches` — `{ "source": "<SecLang>" }`, evaluated before the
    managed rules; wins over the site's own patch source when set.
  - `api_schema` — `{ "openapi_spec": "<JSON>" }`; the document must parse
    as a JSON object, and request-shape findings stay monitor-only.
  - `rate_limit` — `{ "rules": [ ... ] }` with the API's bounds
    (characteristics, period 1–86400s, threshold, action, mitigation);
    shared limits append to the site's own and the edge applies both.
  - `ip_access` — `{ "rules": [ { "name", "ip_ranges", "action" } ] }`
    with CIDR validation and the IP action set; shared rules append to
    the site's own allow/block entries.
  - `bot` — bot posture overrides (switch, action, whitelist, JS/TLS/
    behavioural/IP/DNS verification flags) applied on top of the site's
    row; unset keys keep the site's value.
- **Merge semantics**: `virtual_patches` / `api_schema` / `bot` merge per
  key (overlay keys win); `rate_limit` / `ip_access` merge by rule name
  (an overlay entry replaces the policy's rule); the effective payloads
  are returned by `/sites/{id}/effective-config` and `POST
  /policies/preview` as `layers`.
- **Bundle**: policy rate limits and IP rules join the site's lists with
  namespaced ids (`policy:<id>:rl:<n>` / `policy:<id>:ip:<n>`), patch
  source and OpenAPI document override the site's row, and bot overrides
  are folded into the site's posture before the bundle is signed.
- **Dashboard**: the policy editor now has tabs for all nine layer kinds
  with real editors — SecLang and OpenAPI text editors, bot switches, and
  rule tables for rate limits and IP access. The site Policy tab lists
  the shared layers reaching the site and the overlay editor gained
  **quick-add** buttons that insert a starter snippet per layer kind.
- **Deliberately not built**: a `body` layer (body inspection size is an
  engine-wide constant today) and a `logging` layer (retention is a
  deployment setting) — inventing per-site knobs the engine does not
  honour would repeat exactly the kind of mismatch earlier rounds fixed.

## Verification at release

- `cargo test --workspace` green with new coverage: validation of every
  new layer payload (unknown keys, invalid actions, non-JSON schemas,
  bad CIDRs, out-of-range windows), merge behaviour (bot key merge,
  rate-limit replace-by-name, overlay marks) and the bundle mapping
  (namespaced ids, thresholds, bot overrides, patch precedence). Clippy
  `-D warnings` clean; `tsc -b && vite build` clean.
- Live E2E: a policy with an engine layer, a virtual patch and a shared
  rate limit was assigned to the E2E site — the patched path answered
  **403** while benign traffic stayed **200**, the third request inside
  the window answered **429**, a shared `ip_access` block for the probe
  address answered **403** and removing the layer returned **200**, and
  the effective configuration exposed the bot and API-schema layers.

## The policy model, complete

Nine layer kinds, assignment + sparse overlay, rule tuning in data
(disable / monitor / score override / target exclusions, selectors),
versioned history with diff and rollback, compiled preview, templates and
recipes, and published-vs-applied reporting per node. Deliberate
divergences from the studied product remain: no generic plugin runtime,
no forked engine, no in-band licensing, and no silent "applied" claims.
