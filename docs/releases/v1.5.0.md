# VarmanWAF v1.5.0 — authorization hardening and one data plane

**Release date:** 2026-11-28
**Images:** `sovichetra/varmanwaf:1.5.0`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.5.0`

This release closes the authorization gaps found by the code-health pass and
unifies the data-plane composition behind one assembler.

## Security

- **Forced password change is enforced on every mutation.** All 57
  admin-scoped mutating control-plane handlers call `require_write`, which now
  includes the `must_change_password` gate. Self-service paths (own API keys,
  own AI conversations, profile update) use a flag-only helper, and the
  password-change endpoint stays exempt so an account can clear the flag.
- **Admin plugin.** The unauthenticated `/configs/*.js` bypass is closed; only
  exact `GET`/`HEAD` public assets were ever exempt, and the plugin now serves
  no console at all. Empty or malformed credentials fail plugin construction
  unless `allow_unauthenticated = true`; `--admin` percent-decodes both halves
  of `user:pass@host`; admin imports validate and return 400 on client errors;
  credential-bearing logs are redacted (admin, basic/key/combined auth, JWT,
  challenge, CSRF).
- **IP groups.** Create/update/delete/set-sites/sync are administrator-only,
  and `show`/`list-sites` apply the same visibility rule as `list`.
- **API keys.** `key_allows_agent` is fail-closed: only an explicit `agent`
  permission enrolls an agent. Re-grant `agent` to any legacy key that was
  created without it.
- **Auditor role.** `AuthUser::can_read_all` implements the documented
  read-every-resource behavior for auditors; writes remain administrator-only.
- **MCP.** `ToolContext` carries the caller's subject and read-all capability;
  every tenant tool (sites, agents, access/WAF logs, traffic, certificates,
  control-plane logs, IP groups, `set_site_status`) is scoped.
- **TLS.** Ring is installed explicitly as the rustls provider, matching the
  documented behavior.

## Reliability and structure

- One `src/data_plane.rs::assemble` builds providers, `AppContext`, the pingora
  server and the shared background loops for the daemon, `--cp` and the
  agent-hosted plane. One `src/config_apply.rs` applies reloads; the agent plane
  commits only after providers succeed.
- `WafEngine::inspect` is 52 lines (was 862) and `WafPlugin::handle_request`
  45 (was 900); the data-plane, cache and report modules are split by
  capability.
- Plugin configs are typed and reject unknown keys/wrong TOML types at
  `pingap -t`. This is intentionally stricter: a typo no longer silently takes
  a default.
- `--cp` requires `--admin`; readiness rejects an empty pid report; the restart
  command slot replaces and warns instead of silently keeping the first; the
  memory budget is set once in `main`; the config manager no longer caches a
  failed init.

## Breaking changes

- `--admin` is the data-plane JSON/profiling API only (`/configs`,
  `/config-history`, `/basic`, `/restart`, `/aes`, `/certificates`, `/pprof/*`).
  The console is served by the control plane at `--admin-addr` / `:9080`.
- `--cp` without `--admin` exits with an error.
- `--admin host:port` without credentials fails closed; use
  `user:pass@host:port` or set `allow_unauthenticated = true` explicitly.
- Plugin configuration keys are validated; remove misspelled/extra keys and use
  the documented types (for example `chunk_size = "4KiB"`).
- Bare `varman` and `varman --help` show the Varman parser; `pingap` keeps the
  legacy one.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.5.0
```

No database migration is required.
