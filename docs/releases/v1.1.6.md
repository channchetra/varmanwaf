# VarmanWAF v1.1.6 - Agent stays online with an ACME IP dashboard certificate

**Release date:** 2026-10-22 **Images:** `sovichetra/varmanwaf:1.1.6`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.6`

One production bug from the dashboard-certificate round: after the console
switched to a **Let's Encrypt IP certificate**, the embedded agent could no
longer connect - the Agents page showed **Offline** with a fresh "last
heartbeat" and commands queued, and the log repeated
`Connection to control plane failed error=transport error`.

## Root cause (two independent mismatches)

All-in-one serves gRPC (9090) with the **active control-plane certificate**
and injects that same PEM into the embedded agent as its trust anchor.
That worked only for the generated self-signed certificate:

1. **The anchor must be a CA.** An ACME certificate is a *leaf followed by
   the issuer chain*; the code pinned the whole PEM, i.e. the **leaf** first.
   webpki rejects a non-CA leaf as a trust anchor, so the chain could never
   verify.
2. **The name must match the certificate.** The agent dials
   `https://127.0.0.1:9090`, so hostname verification checks the URL host.
   The self-signed certificate carries `localhost` / `127.0.0.1` / `::1`;
   an ACME **IP** certificate carries only the management IP
   (`103.189.187.19`), so verification failed.

A running process kept its already-open channel, which is why the agent only
went offline at the next container recreate.

## Fix

- `embedded_agent_ca_pem` now returns `EmbeddedAgentTls { ca_pem, tls_name }`:
  - `trust_anchor_pem` pins the **issuer chain** (everything after the leaf)
    when the certificate has one, and the leaf itself for the single
    self-signed certificate (its own root).
  - `preferred_tls_name` picks `localhost` / `127.0.0.1` / `::1` when the
    certificate carries one, otherwise its first SAN (the ACME IP), and
    `AgentConfig.server_tls_name` feeds tonic's `domain_name`.
- Split deployments with explicit `grpc_tls_cert` files keep tonic's default
  (the URL host), unchanged.
- Tests: loopback-name preference, IP-SAN selection, no-SAN fallback,
  chain splitting (leaf vs issuer), single-certificate anchor, and
  garbage/empty PEM.

## Verification at release (before/after on the same host)

A CA-signed chain whose only SAN is `203.0.113.7` (an ACME-IP stand-in) was
uploaded as the dashboard certificate:

- **1.1.5**: agent `offline`, `connected=false`, repeating
  `transport error` - the reported symptom reproduced.
- **1.1.6**: startup logs `embedded agent gRPC certificate name
  tls_name=Some("203.0.113.7")`, then `Connected to control plane` -
  agent `online`, `connected=true`, heartbeats and config sync resume.
- After restoring the generated self-signed certificate the agent stays
  online as well; console tsc/eslint clean, vitest 25/25; full 45-script
  E2E sweep on the deployed build (45/45).

## Upgrading (unblocks an affected instance)

```bash
cd ~/varmanwaf && docker compose pull
docker compose up -d --force-recreate varman
```
The agent reconnects within ~30 seconds; queued commands drain and the
Agents page flips to Online. Keep the ACME IP certificate enabled - no need
to fall back to self-signed.
