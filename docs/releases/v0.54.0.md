# VarmanWAF v0.54.0 - API assets: the observed inventory

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.54.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.54.0`

The second Tiyi port from `tiyi-analysis/api-assets-and-country-access.md`:
the observation half of their API pipeline - an endpoint inventory built from
real traffic, marked against the declared document. Patterns only; nothing
is copied from Tiyi.

## What this round brings

- **`GET /sites/{id}/api-assets?days=&limit=`**: method+path aggregates over
  stored access logs (bounded: 1-30 days, max 500 rows, default 7/200),
  ranked by request count with 5xx counts and first/last seen. No bodies,
  no parameters - the same honesty rule as Tiyi's bounded learning, without
  the learning yet.
- **Coverage against the declared document**: each observed endpoint is
  matched to the site's OpenAPI `paths` - exact template first, then
  segment-by-segment with `{param}` placeholders - and marked in-spec /
  not-in-spec with the matched template. An unparsable document is
  reported, never guessed; a missing one leaves coverage unmarked.
- **The other direction**: **declared-but-unused** operations (in the
  document, no traffic in the window). It is only computed on a complete
  observed list - when the cap truncates, the page says so instead of
  guessing.
- **Site -> Security -> API assets** (tab bar, new page): spec status card,
  window picker, the observed table, the declared-but-unused list, and the
  explicit limitations (logs bound the window; path parameters are not
  learned; an endpoint never called cannot appear).

## Verification at release

- `cargo fmt --check` exit 0; control tests **367 passed** (new: spec
  parsing incl. `x-` keys and invalid documents, exact-then-template
  matching, trailing-slash handling); plugin tests **194**; clippy
  `-D warnings` clean; web tsc/eslint/vite clean, 20/20 unit tests,
  markers present.
- Live E2E (api-assets script): with no document the inventory reports
  observed traffic and the no-spec limitation; after probing `/users/42`
  and `/admin` (answered by the WAF itself - pass-through 5xx responses are
  not access-logged, so the probes use the geo block on unknown countries)
  and setting a two-operation document, the template match marks
  `/users/42` in-spec as `/users/{id}`, `/admin` stays not-in-spec,
  `post /orders` is declared-but-unused, the clamped windows answer
  (999 -> 30, 0 -> 1), an unscoped viewer is refused exactly like an
  unknown site (`404`, no existence leak), and both the original document
  and the geo policy are restored.
