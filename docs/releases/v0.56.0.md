# VarmanWAF v0.56.0 - Exclusion packages (path-scoped rule exclusions)

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.56.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.56.0`

The exclusion-package surface the operator asked for, learned from Tiyi's
policy-tuning UX: curated exclusion sets for well-known applications,
attached to a site **at a path prefix**. Patterns only; every entry's
content is ours and states what it excludes.

## What this round brings

- **Path-scoped rule exclusions in the engine**: target exclusions
  (path/query/body/header/cookie/user_agent/host/method) can now carry a
  **path prefix** - the exclusion applies only while the request path
  starts with it, and merges with the policy's site-wide exclusions. New
  `PathTargetExclusion` in the engine config, carried through the protocol
  (`RuleTargetExclusions.path_prefix`) and the agent cache.
- **The catalogue** (seeded, versioned, editable): **WordPress admin &
  REST** (the CMS-probe rule and the rich-text XSS body exclusion under
  `/wp-admin`), **Next.js static assets** (long-URI rule under `/_next`),
  **Nextcloud WebDAV** (long-URI + dotfile rules under `/remote.php`),
  **Rich-text editors (generic)**. Each entry carries a note stating the
  exclusion and its trade-off; nothing applies until attached.
- **API**: `GET /exclusion-packages` (catalogue), `POST` (custom packages,
  validated against the managed-rule ids and the target set),
  `GET/POST /sites/{id}/exclusion-bindings` (attach at a prefix),
  `PUT` (enable/disable, re-prefix, reinstall when the package version
  moved), `DELETE`. Every mutation **re-pushes the site's bundle**.
- **Console**: a new **Exclusions** tab on the site's Protection page -
  attached bindings (toggle, reinstall when stale, remove) and the
  catalogue with per-package attach + path prefix. Each entry renders its
  rule, its excluded sources and its note, plus the standing review hint:
  *an exclusion is a scoped blind spot for the listed rules*.
