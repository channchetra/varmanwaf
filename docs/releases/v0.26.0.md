# VarmanWAF v0.26.0 - Policy & Rule Control Plane, round 3 (P3: fine tuning)

**Release date:** 2026-10-13 • **Images:** `sovichetra/varmanwaf:0.26.0`,
`sovichetra/varmanwaf:latest` • **Tag:** `v0.26.0`

Round P3 of the Tiyi-informed control model: **fine-grained rule tuning and
a compiled preview**. Rules can now exclude the request targets that cause
false positives, selectors tune whole rule families at once, and operators
can see exactly what the data plane will do before publishing.

## What this round brings

- **Target exclusions** (`exclude_targets` on override entries): `path`,
  `query`, `body`, `header`, `cookie`, `user_agent`, `host`, `method`.
  Engine semantics: a rule that still matches against a context with those
  targets neutralized keeps firing; a match that *depends* on an excluded
  target is suppressed. Score-consumer rules (`cf.waf.score.*`) read
  aggregates rather than request targets, so exclusions never suppress
  them — documented and regression-tested. The filtered context is only
  built for rules that carry exclusions, so the hot path is unchanged.
- **Tag and severity selectors**: an override entry may address rules by
  `tags` (any catalogue tag) or `severity_min` (rules at or above the
  level) instead of `rule_id`. Selectors expand against the managed-rule
  catalogue during resolution; exact `rule_id` entries apply afterwards
  and always win. Unknown tags are rejected at write time, and every entry
  must use exactly one addressing mode.
- **Compiled rule plan**: `GET /sites/{id}/effective-config` now returns a
  `plan` — per managed rule: catalogue metadata, `enforce` / `monitor` /
  `disabled`, the anomaly score it contributes (override or severity
  default) and its exclusions. `POST /policies/preview` compiles a draft
  (a policy's stored layers plus draft layers, with the site overlay and
  settings when a `site_id` is given) **without saving anything**, so an
  operator can preview a change before publishing.
- **Dashboard**: the Rule tuning tab gains per-rule exclusion pickers,
  read-only chips for selector entries and a **Preview plan** dialog; the
  site Policy tab shows the compiled rule plan for the effective
  configuration.
- **Protocol/agent**: `WafConfig.rule_target_exclusions = 50` (a repeated
  `RuleTargetExclusions` message); the agent cache defaults the field for
  caches written before this release.

## Verification at release

- `cargo test --workspace` green with new coverage: engine tests proving
  exclusions suppress only dependent matches (path excluded → no match;
  unrelated exclusion → still blocks; aggregate rules unaffected); plugin
  tests for the bundle fields; control-plane tests for selector
  validation (exactly-one addressing, unknown tag, unknown target), tag
  and severity expansion with exact-entry precedence, and the compiled
  rule plan (effective state, override score, exclusions). Clippy
  `-D warnings` clean; `tsc -b && vite build` clean.
- Live E2E: a blocking policy on the E2E site returned **403** with a
  `block|9` event for the dotfile probe; `monitor + exclude_targets:
  ["path"]` answered **200** with **no event** for the rule (the match was
  suppressed, not just downgraded); plain `monitor` answered **200** with
  a `monitor|9` event; a `tags: ["dotfile"]` selector entry disabled the
  rule (**200**, no event) and the plan showed it `disabled`; the preview
  endpoint compiled a `severity_min: 5` draft showing the critical rules
  as `monitor`; removing the layer restored **403**/`block|9`.

## Not in this round (P4-P6)

(P4); templates and recipes (P5); remaining layers (body, api_schema,
ip_access, rate_limit, bot, logging) and the full overlay UI (P6). See
