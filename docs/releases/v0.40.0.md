# VarmanWAF v0.40.0 - Batch 4b: ops surfaces (IP blacklist, notifications, failover, geo map)

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.40.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.40.0`

Batch 4 continues with the operational surfaces the upstream dashboard
gained, plus the IP-list import hardening promised in the v0.39.1 round.
The server side already implemented every endpoint these pages call; this
round is the console work, the API/type deltas and the tests.

## What this round brings

- **IP Blacklist** (`/blocked-ips`): the global cross-site view of dynamic
  blocks - WAF/rate-limit auto-blocks plus manual blocks - each row folded
  per (site, IP) with its attack counts. Filters by site and IP, a manual
  block dialog (10 minutes to permanent, fanned out to every registered
  agent and queued for offline ones), one-click unblock, 30 s polling
  because blocks appear and expire without user action.
- **Notifications** (`/notifications`): delivery thresholds and the ten
  per-event toggles, the login-security card (anomaly baseline, trusted
  header, online geo template, MaxMind mmdb upload, recent login history)
  and the paged alert history with an event-type filter. Two deliberate
  divergences, recorded: **channel CRUD stays on the Alerts page** (one
  owner for delivery targets instead of two editors), and non-admin
  accounts see the page overview plus an explicit note rather than a wall
  of 403s - settings, login security and history are administrator-only
  server-side and the page now mirrors that.
- **World map on the traffic pages**: a requests-per-country choropleth
  rendered from bundled TopoJSON (`world-atlas`) through `d3-geo` - no
  runtime map service. Site pages read the per-site stats endpoint (a
  fixed 24-hour window); the global page reads the cross-site aggregate
  (`/geo/global-stats`) over the selected range.
- **Site Settings is a real page** (it was a stub placeholder): it hosts
  the disconnected-edge failover policy - `inherit` (the resolved global
  default is spelled out), `open`, `closed` - pushed to agents with the
  next configuration sync.
- **`wafLinkage` helpers ported with tests**: `applyCategoryLinkage`
  returns the single WAF-settings payload that keeps a category switch and
  the managed rules of its family in step; the vitest suite covers the
  add/remove/idempotence and independent-override cases. The rule ids in
  the fixtures are our `VARMAN-` catalogue's. (Groundwork: no production
  caller yet - the next round wires it into the rule surfaces.)
- **IP-list import hardening** (queued from v0.39.1): the subscription
  fetch now retries once after a transient failure before recording the
  error, so a network hiccup on import (or a daily refresh) no longer
  leaves the group empty until the next schedule; and the catalog dialog
  keeps a failed first fetch on screen with a **Retry sync** action, shows
  a duplicate (409) as an informational "already imported" banner naming
  the existing subscription, and reports parse-level failures the same way
  it always did - nothing is swallowed.
- **Web tests exist now**: `vitest` joins the toolchain (`npm test`), so
  the workspace graph and result widgets can keep gaining unit coverage.

## Verification at release

- `npx tsc -b` and `npx vite build` clean; every new surface verified
  present in the built bundle; `npx vitest run`: 6/6 (wafLinkage); eslint
  reports only the two pre-existing router warnings.
- `cargo test -p varman-control` green (348); clippy `-D warnings` clean.
- Live E2E (batch 4b script) against the deployed build: a manual block
  of `203.0.113.77` fanned out to the single registered agent
  (`delivered=1`), appeared on the site list and on the global list with
  its site name and reason, and the unblock lifted it everywhere; the
  failover policy round-tripped (`inherit` -> `open` -> `inherit`,
  restored); the notification settings saved back unchanged; the event
  page and the event-type list (including `security.alert`) answered;
  login security answered and the login history is populated (newest
  `admin@varman.local` from `172.20.0.1`, source `private`); the geo
  stats answered on both scopes - and honestly showed almost no country
  data (country codes exist for 1 of 398 access logs), so the map renders
  empty until the edge resolves countries; and a viewer account read the
  block list (own sites only) while `/notifications/settings` and
  `/login-security` answered 403 - exactly the gating the page mirrors.
