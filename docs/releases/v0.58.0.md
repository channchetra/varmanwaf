# VarmanWAF v0.58.0 - API assets: bounded learning + OpenAPI draft

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.58.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.58.0`

The learning half of the Tiyi API pipeline, built on v0.54.0's observed
inventory: structures and counts from real traffic, an explicit OpenAPI
draft export, and the same honesty rules throughout. Patterns only.

## What this round brings

- **Bounded structural learning** (`POST /sites/{id}/api-assets/learn`):
  reads the window's stored JSON request bodies and query strings and
  merges **structure only** - keys, JSON types, presence counts. Values are
  never read out of a sample (a test asserts distinctive sample values
  never appear in the stored structure). Every dimension is bounded: depth
  8, 100 keys per object, 50 query parameters, 20 array elements per
  sample, 5000 scanned rows; **truncated bodies are skipped and counted**,
  never guessed at.
- **`api_learned_schemas`** (one row per observed method+path): the merged
  request structure, query parameter types/counts, sample counts and
  first/last seen. Each learn run replaces the endpoint's row with the
  window's aggregate, so a stored structure always reflects a stated
  window.
- **OpenAPI draft export** (`GET /sites/{id}/api-assets/openapi-draft`):
  a 3.0.3 document from the learned rows - templatized paths
  (`/orders/42` -> `/orders/{id}`), query parameters with observed counts,
  request bodies with `x-observed-presence` extensions, and **no `required`
  lists anywhere**; the description states exactly what it is (structures
  and counts, no values, response shapes not learned yet).
- **Console**: the API assets page gains the **Learn shapes** card (window
  picker, run, summary with skipped counts and the scan-cap note), the
  learned-structure table (method, path, samples, keys, last seen) and
  **Download OpenAPI draft** (fetched with the caller's token).

## Verification at release

- `cargo fmt --check` exit 0; control tests **376** (new: merge/type/presence
  semantics, bounds, query classification, templatization, draft honesty -
  no values, no `required`); plugin **200**; agent **42**; engine **494**;
  clippy `-D warnings` clean; web tsc/eslint/vite clean, 20/20 unit tests.
- Live E2E (learning script): JSON requests with distinctive values (and an
  attack payload that gets the request blocked, which is what puts the body
  in the stored logs) -> a learn run reports the endpoints and samples ->
  the learned structure contains the keys but **none of the values** ->
  the draft downloads, parses, and carries `/orders` with
  `x-observed-presence` and no `required` lists; the probe IP is unblocked
  afterwards.
