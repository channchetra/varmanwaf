# VarmanWAF v1.3.2 — TCP port forwarding removed from the WAF

**Release date:** 2026-10-28
**Images:** `sovichetra/varmanwaf:1.3.2`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.3.2`

Correction release. TCP port forwarding does not belong in a WAF.

## Why

A WAF is an HTTP(S) reverse proxy with request inspection, TLS termination and
origin protection. Arbitrary TCP forwarding (SSH, RDP, databases) is a network
function: it belongs to the **host firewall** (`nftables`/`ufw`), a **VPN**
(WireGuard, Tailscale), a **bastion/jump host**, or a dedicated TCP proxy. A
WAF-managed forward bypasses HTTP inspection and creates a second, weaker
access-control model.

The feature shipped in v1.3.0/v1.3.1 but was unused: `port_forwards` had zero
rows, and the published `10000-10099` range was already closed on production.

## What was removed

- The **Port forwarding** site page, route, navigation link and translations.
- The REST API (`/sites/{id}/port-forwards`) and the `port_forwards` model.
- The agent TCP listener manager.
- The `PortForward` protocol message and the `SiteConfig` field.
- The `ipnet` dependency that only the listener used.
- Migration **067** drops the empty `port_forwards` table.
- The compose file no longer publishes `10000-10099`.
- Current user-guide and deployment guidance for the feature.

The v1.3.0/v1.3.1 release notes stay as history and carry a removal banner.

## What remains

All of the v1.3.x certificate and security work is unchanged:

- certificate-only changes reload the edge (`data_plane_hash`);
- API-key prefix panic fixed;
- cross-tenant log read fixed;
- ACME scans every minute with exponential backoff.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.3.2
```

Migration 067 runs automatically and drops the empty table. No site
configuration is affected.
