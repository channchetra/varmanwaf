# VarmanWAF v0.50.0 - Protection section: CRS folded under Policies, deep-linkable alerts

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.50.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.50.0`

Applying the navigation study's remaining conclusions - the last queued
items in [`docs/navigation-ia.md`](../navigation-ia.md#protection-section-v0500).

## What this round brings

- **CRS rulesets folded under Policies**: both pages share a
  **Policies | CRS rulesets** section tab strip (route-based, so
  `/policies` and `/crs` both keep working as deep links), and the CRS
  entry left the sidebar - one fewer menu item with the same reachability.
- **The "rules umbrella" question resolved**: the policy editor already
  carries a layer tab strip including the **crs**, **custom rules** and
  **rule overrides** layers, so the rule surfaces were already grouped
  where they are edited; no new hub page was needed.
- **`/alerts` is deep-linkable**: the section pills update the URL hash
  (`/alerts#delivery`), an incoming hash scrolls to its section once the
  page has painted, and a scroll-spy lights the pill of the section in
  view - the section nav is now a real navigation surface, not just a
  scroll shortcut.

## Verification at release

- `npx tsc -b`, `npx vite build` and eslint clean (the hooks-order slip in
  the first pass was caught by eslint and fixed); 20/20 web unit tests;
  bundle markers for the section tabs and the alerts sections.
- Live E2E (protection-section script): version and health; both
  `/policies` and `/crs` serve the console; the CRS ruleset API behind the
  tab answers; the alerts route serves; markers present. The hash/scroll
  behaviour is client-side and not curl-verifiable - stated, not claimed.
- No Rust edits: the server is byte-identical to v0.49.0.
