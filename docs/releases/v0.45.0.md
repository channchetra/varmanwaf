# VarmanWAF v0.45.0 - Interception reports: summary on the dashboard, full report on download

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.45.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.45.0`

The report generator lands: the console keeps only light aggregates, and
the complete interception report is generated on demand and downloaded as
a self-contained HTML file - built on our own data and layout, modelled on
the report shape operators already know (types, attack-IP and URL
rankings over a date range), not on any third-party assets.

## What this round brings

- **`GET /reports/summary`** (admin): totals (interceptions, blocked,
  monitor-only, unique IPs/paths), the top type / country / IP and a
  bounded daily series - the only thing the console loads. The dashboard
  gains a compact 30-day summary card linking to the page.
- **`GET /reports/interception`** (admin): the full report as an HTML
  **attachment**, generated when asked:
  - cover header (brand, range, scope, generated-at, operator), summary
    cards, interception types with counts/share bars (rule groups
    classified through the managed-rule catalogue - SQL injection,
    XSS, bot protection, custom rules by name...), a daily timeline
    (total vs blocked), attack-IP ranking TOP20 (country, last seen) and
    URL ranking TOP20;
  - **fully self-contained**: inline CSS only, no scripts, no external
    assets; opens offline, prints to A4;
  - **bounded**: ranges capped at 92 days, top-20 lists, daily series by
    range - generation stays cheap;
  - **honest**: monitor-only decisions are included and labelled, the
    footer states the counts are stored events (not sampled), and
    countries appear only when the edge resolved them;
  - every stored string (paths, IPs, rule names) is HTML-escaped - report
    data is attacker-reachable and must never render as markup (unit
    tested).
- **Reports page** (`/reports`, admin-gated like the routes): range
  presets (24h/7d/30d/90d/custom dates), scope picker (all sites or one),
  the summary strip, and **Generate & download** (authenticated blob
  fetch; the file name comes from the server's `Content-Disposition`).
- Tests: server-side window bounds (defaults, whole-day end dates, order
  and the 92-day cap), catalogue classification fallbacks, HTML escaping
  and a full render assertion (self-contained, data escaped); web range
  helper tests.

## Verification at release

- `cargo fmt --check`, control tests **355 passed** (+6), clippy
  `-D warnings` clean; web `tsc`/vite clean, **20/20** unit tests, bundle
  markers for the page, its overview box and the dashboard card.
- Live E2E (reports script): the summary answers for a 30-day window; the
  report downloads with `text/html` + `Content-Disposition: attachment`,
  starts with `<!DOCTYPE html>`, contains the four sections, the site
  scope when filtered, and **no `<script`**; an over-92-day range and an
  invalid date are rejected (400); a viewer account gets 403 on both
  endpoints.
