# VarmanWAF v1.2.5 — the Agents page reports the sites the edge really serves

**Release date:** 2026-10-27
**Images:** `sovichetra/varmanwaf:1.2.5`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.5`

Patch release for a dashboard inventory bug. The proxy was serving every site,
but the Agents page and fleet topology under-counted the embedded agent.

## The bug

v1.2.4 made the embedded all-in-one agent serve every site on the instance,
regardless of which admin owned it. That fix covered the gRPC config paths:

- `register_agent` / `GetSiteConfig` (what the edge runs);
- `UpdateSite` pushes (when a site changes).

The REST agents API had a **third copy** of the old visibility rule. It still
scoped an unbound agent to the sites owned by its API key's user. As a result:

- the Agents page showed `all sites (1)` while the engine log said `sites=2`;
- the fleet topology showed the second site as `no agent`, even though the
  edge was serving it and its certificate was loaded.

The data plane was correct; only the inventory display was wrong. That is
still confusing during an incident, because the page suggests a site has no
edge.

## The fix

- The agents inventory now uses the same bootstrap-key predicate as the gRPC
  paths. An unbound agent holding `_all-in-one-bootstrap` lists **every site**;
  ordinary, enrollment and bound agents keep their existing scope.
- The site-filtered agent list also includes the embedded agent for any site it
  serves, so filtering the Agents page by the second site no longer hides it.
- Resolving the served sites was extracted into a pure helper with a
  regression test covering bootstrap, ordinary and bound keys.

## Verification

- `cargo test -p varman-control --lib api::agents` → **6 passed**.
- The new test covers the bootstrap key, an ordinary key, a bound agent and a
  row without a key.
- After the upgrade, the Agents page shows `all sites (2)` and both topology
  nodes show `served by 1` for the same data plane.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.5
```

No migration and no configuration change. Roll back with `1.2.4` if needed;
1.2.5 only changes inventory reporting.
