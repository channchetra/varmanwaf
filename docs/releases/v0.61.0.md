# VarmanWAF v0.61.0 - Per-operation API controls (Off / Observe / Enforce)

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.61.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.61.0`

The Tiyi pattern applied to the learned inventory: every observed endpoint
gets a control that decides how the OpenAPI validation layer treats it -
**off** skips it, **observe** records findings as monitor (the layer's
historical behaviour, and the default), **enforce** escalates them to a
block.

## What this round brings

- **`api_learned_schemas.mode`** (default `observe`) + the learned rows now
  carry their control; `PUT /sites/{id}/api-assets/learned/{row_id}/mode`
  (writers) validates and stores it, and the same call **pushes the
  bundle**, so "set" and "applied" never drift.
- **The controls travel in the bundle** (`WafConfig.api_operations`,
  method + templatized path + mode) and compile into the plugin's custom
  layers: the layer matches the request against the learned templates and
  applies the mode - off returns before any validation, enforce turns the
  finding into a block, observe records. Unknown modes are reported and
  ignored (a stale cache), never guessed at.
- **Templates, not raw paths**: `/orders/42` and `/orders/43` collapse to
  `/orders/{id}`; when several observed paths map to one template the
  **most restrictive** mode wins (enforce > observe > off).
- **Console**: the learned-structure table gains a **Control** column
  (Off / Observe / Enforce) with the note that it gates schema validation
  for that endpoint and reaches the edge in the same call.

## Honest scope

The control gates the **OpenAPI validation layer** (the spec-based checks:
unknown operation, method, required parameters, body schema) - not the
native WAF engine, which keeps its own per-site and per-rule controls. The
console states exactly that.
