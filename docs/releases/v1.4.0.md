# VarmanWAF v1.4.0 — Multi-domain certificates and policy backup

**Release date:** 2026-11-02
**Images:** `sovichetra/varmanwaf:1.4.0`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.4.0`

> **Superseded:** [v1.4.2](./v1.4.2.md) includes these features and fixes
> WebSocket stream enforcement. Deploy v1.4.2.

Two operational features: one certificate can cover several hostnames and be
shared across sites, and WAF policies can be exported to JSON and imported
again.

## Multi-domain certificates

- Certificate creation accepts a `domains` array (and the legacy
  comma-separated `domain` field). Every hostname is normalised and deduped.
- The ACME order and the certificate entry the edge serves use the SAN list,
  so one order can cover `example.com`, `www.example.com` and
  `*.example.com` (wildcards still require DNS-01).
- Imported certificates (a PEM/key pair) can be selected on another site.
  The picker lists imported certificates whose SAN list covers every hostname
  of the site; selecting one creates a binding instead of copying the private
  key. Updating the owner's PEM refreshes the bound sites' configuration.
- ACME-managed certificates stay with their owner site: their private key
  never reaches the control plane, so they cannot be served or renewed by
  another site.
- Migration **068** creates `site_certificate_bindings` with cascading
  foreign keys and a uniqueness constraint on `(certificate_id, site_id)`.
- Deleting a shared certificate clears the selection on every bound site.

## Policy JSON import/export

- `GET /api/v1/policies/{id}/export` — one policy as a portable document.
- `GET /api/v1/policies/export` — every policy in one backup file.
- `POST /api/v1/policies/import` — accepts either shape, validates every
  layer before writing, and creates new policies. Name collisions get an
  `(imported)` suffix; imports never overwrite a live policy.
- The Policies page has **Import**, **Export all** and a per-policy
  **Export** action. Site assignments and revisions are not part of the
  document: restore the definitions, then assign them in the site's Policy
  tab.

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.4.0
```

Migration 068 runs automatically. Existing single-domain certificates and
policies are unchanged.
