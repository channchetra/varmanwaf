# VarmanWAF v1.2.1 — full-width topology on desktop

**Release date:** 2026-10-25
**Images:** `sovichetra/varmanwaf:1.2.1`, `sovichetra/varmanwaf:latest`
**Tag:** `v1.2.1`

Patch release for the topology canvas on wide desktop displays.

## What changed

The app shell caps every page at `max-w-[1400px]`. The topology stage already
cancelled the shell padding, but not that content cap, so on a 1920 px display
the canvas still started ~140 px inside the main column and looked boxed in.

- `/topology` and `/sites/:siteId/topology` now bypass the 1400 px content cap
  and use the whole main column; every other page keeps the existing reading
  measure.
- The stage starts at the sidebar edge and ends at the viewport edge. Measured
  at 1920 × 994: **left 240 px, width 1680 px, right 1920 px**; the dashboard
  still measures **1400 px centred**.
- No other markup, API or database change.

## Verification

- `tsc -b`, Vitest 42/42, ESLint 0 errors and the production build pass.
- Headless Firefox at 1920 px: fleet and site canvases are full-bleed; the
  floating chrome sits 16 px inside the canvas; the dashboard keeps the
  1400 px measure.
- Full topology checks from 1.2.0 still apply (docked editor, node
  re-centring, add rail, fit, fullscreen, narrow sheet, reduced motion).

## Upgrade

```bash
docker compose pull varman
docker compose up -d --force-recreate varman
curl -sk https://localhost:9080/api/v1/version   # -> 1.2.1
```

No migration and no configuration change. Roll back with the `1.2.0` tag.
