# VarmanWAF v0.39.1 - Fix: the first-sign-in gate engages; login history restored

**Release date:** 2026-10-14 **Images:** `sovichetra/varmanwaf:0.39.1`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.39.1`

Two backend fixes found by the v0.39.0 (batch 4a) release E2E, caught before
any images were published. This release carries batch 4a; the dashboard
bundle is unchanged from v0.39.0.

## The bugs

1. **Administrator-created accounts were not forced to change their
   password.** `POST /api/v1/users` created accounts through the shared
   `create_user` helper, which hard-coded `must_change_password = false`.
   The console's non-dismissible first-sign-in dialog keys on that flag
   (and `require_write` refuses mutations while it is set), so the gate the
   round promised never engaged for admin-created accounts. The bootstrap
   administrator was unaffected - `lib.rs` sets the flag explicitly.

2. **No login was ever recorded.** Both login handlers extracted the TCP
   peer as `Option<Extension<ConnInfo>>`, but axum inserts
   `ConnectInfo<ConnInfo>` - the wrong type never matches and silently
   yields `None`. `resolve_client_ip` then returned `None` and
   `record_login` returned early at `debug` level, so `login_history`
   stayed empty: the user list's last-login column had nothing to show and
   the login-anomaly alert had no baseline to compare against.

## The fixes

- `create_user` gained a `must_change_password` parameter: the register
  path passes `false` (the account holder chose the password), the admin
  `POST /users` path passes `true` (the administrator typed a temporary
  one).
- `auth::login` and `passkeys::login_finish` extract
  `Extension<ConnectInfo<ConnInfo>>` - the type axum actually inserts,
  matching `api_protection` and the request middleware. Passkey sign-ins
  were broken the same way (recorded, never judged).
- `record_login` never skips the history row: without a resolvable client
  IP it stores `unknown` (no geo lookup, no judging) and logs at info
  level, so a missing address shows up in the list instead of silently
  eating the audit trail. The stored-IP mapping is a small tested helper.
- The E2E script was hardened: it asserts the created account's flag,
  polls for the detached history write, and checks the administrator's own
  role change is refused (`400`) - the earlier version mis-read that
  response.

## Verification

- `cargo test -p varman-control`: **348 passed** (one new: the
  missing-address marker); clippy `-D warnings` clean.
- Live E2E (account & identity): the created account comes back with
  `must_change_password: true`; its first sign-in carries the flag;
  replacing the password clears it and revokes the old token (`401`); the
  admin list shows the account with its last login **and IP**; a role
  change revokes the token immediately; disabling refuses sign-in,
  re-enabling restores it; the administrator's own role change is refused.
- History rows recorded before this release cannot be reconstructed; the
  login-anomaly baseline starts fresh from here.
