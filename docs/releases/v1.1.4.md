# VarmanWAF v1.1.4 - Auto-issued dashboard certificate (domain or IP)

**Release date:** 2026-10-22 **Images:** `sovichetra/varmanwaf:1.1.4`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.4`

The management console can now present a trusted Let's Encrypt certificate
for its **own domain or its management IP**, issued and renewed automatically
- no more self-signed warnings, no manual uploads, no 6-day renewals by hand.

## What this round adds

- **ACME for the control-plane listener** (`/system/tls/acme`). Settings ->
  *Control plane HTTPS* gained an **Auto-issue (Let's Encrypt)** block: enter
  a domain or an IP and a contact address, arm it, and the dashboard shows
  *Issuing... / Issued / Failed* plus the reason.
  - **Domain**: point the DNS record at this host; the edge answers the
    HTTP-01 challenge. The challenge handler serves `/.well-known/acme-
    challenge/*` **before host routing**, so a dashboard domain that is not a
    proxied site works too.
  - **Management IP**: ordered as an RFC 8738 **IP identifier** - IPv4 and
    IPv6 - under Let's Encrypt's **`shortlived` profile** (~6-day
    certificates). The ACME task renews them on its normal cycle and the new
    certificate is installed without a restart.
- **The certificate lands where the listener reads it.** The data plane adds
  a reserved `__management` certificate entry, the ACME task fills it, and
  the material is handed back to the control plane, which installs it on the
  9080 listener and persists it (`control_plane_certificates`,
  `source = acme`). Installation is idempotent: the stored fingerprint means
  a restart does not re-install and a renewal installs exactly once.
- **Identity edits cannot serve the wrong certificate.** When the requested
  identity changes, the config merge no longer inherits the previous PEM
  (the old certificate does not cover the new name), and the installer
  refuses material issued for a different identity.
- **Clear failure states.** A request that produces no certificate within 30
  minutes is marked **failed** with a reason pointing at the edge/all-in-one
  requirement and the SSL Application log; **Retry now** re-arms it. The raw
  ACME transcript appears in the Application log as before.
- **Honest scope.** Auto-issue needs the edge to share the process (the
  all-in-one deployment) because the edge owns port 80 and the challenge
  store. In a split deployment the API returns a clear 422 and upload /
  self-signed keep working; a manual upload still replaces an ACME
  certificate at any time.
- **Control-plane IP denylist.** The console's IP allowlist answers "who may
  reach the panel"; the new denylist refuses specific addresses even when the
  allowlist accepts them - a denial always wins, both gates run on the TCP
  peer, health probes stay exempt, and denying the caller's own address is
  refused unless forced (`ip_denylist_enabled` / `ip_denylist_ranges` on
  `/settings/api-protection`, with a section in *Settings -> API
  protection*).
- **Docs**: a `features.md` section, a Khmer-guide section (១៦.៣, including
  the domain recipe and the API-protection allowlist), and the API surface in
  `docs/api.md`.

## Verification at release

- `pingap-acme`: 3 new tests - DNS names stay DNS identifiers, IP literals
  become IP identifiers with the `shortlived` profile, mixed orders switch
  too (11/11 in the crate).
- `varman-control`: 6 new tests - identity/email validation (domains, IPv4,
  IPv6, rejected schemes/paths/garbage), revision bumps on retry, the
  reserved entry name, and the install decision (identity match + changed
  fingerprint, idempotent on the same certificate, refuses a previous
  identity's certificate).
- IP gates: 4 new tests - a denylist entry wins over the allowlist, the
  denylist works without the allowlist, the allowlist alone still gates, and
  both gates off allow everything.
- Console: tsc clean, eslint 0 errors, vitest 25/25.
- E2E: `run-e2e-management-cert.ps1` arms a request on the live stack,
  verifies the edge creates the ACME order (raw transcript names the
  identity), leaves the active certificate untouched, and disarms cleanly;
  `run-e2e-api-denylist.ps1` arms a denylist entry for another address,
  checks validation and the self-lockout guard, and restores the posture.
  The full 45-script sweep passes on the deployed build (45/45).
- Live issuance with a real public identity is verified on a production
  deployment (a public IP and port 80 are required; a lab cannot complete a
  Let's Encrypt order).
