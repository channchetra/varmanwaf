# VarmanWAF v0.21.1 — post-rollout completion

**Release date:** 2026-10-08 · **Images:** `sovichetra/varmanwaf:0.21.1`,
`sovichetra/varmanwaf:latest` · **Tag:** `v0.21.1`

Completes every item that v0.21.0 listed as post-rollout, on top of the same
architecture. No configuration changes are required to upgrade.

## Highlights

- **Tail inspection (Phase 5).** The request-body chunks the early read pass
  does not consume (the tail of a body larger than the 64 KiB inspection
  window) now flow through a read-only proxy hook
  (`Plugin::handle_request_body`, called from `request_body_filter`). The WAF
  scans them with a 256-byte sliding window, so a payload split across chunk
  boundaries is still seen; a confirmed payload aborts the request and records
  a security event. `tail_inspection = false` disables the scan.
- **WebSocket frame inspection (Phase 8).** Once a connection carries a 101
  upgrade, the raw tunnel bytes reach read-only hooks in both directions
  (`handle_request_body` for client frames, `handle_upgraded_body` for server
  frames - the response-body hooks stay skipped so rewriting plugins cannot
  corrupt the tunnel, #114). A streaming RFC 6455 decoder assembles fragmented
  messages, handles control frames and fails the connection on malformed
  frames; complete message payloads are scanned with the injection detectors.
  Findings abort the connection and record `ws.*` events; a 101 that is not a
  WebSocket upgrade is never decoded. `ws_inspection = false` disables it.
- **Full JSON-Schema body validation (Phase 8).** OpenAPI `requestBody`
  schemas are enforced: `$ref` into `components.schemas`, `type`, `nullable`,
  `enum`, `required`, `properties`, `additionalProperties: false`, `items`,
  `minItems`/`maxItems`, `minLength`/`maxLength`, `pattern`, numeric bounds
  and `allOf`/`anyOf`/`oneOf`. Violations record
  `api.schema_violation` (Monitor) with a JSON-pointer detail; a truncated
  capture is skipped, never misreported.
- **SQL AST tier (Phase 6).** A dialect-aware detector
  (`semantic.sql.ast`, `sqlparser`) parses SQL-ish values - full statements
  directly, fragments through statement templates - and blocks stacked
  statements, UNION/EXCEPT/INTERSECT queries, tautological predicates and
  DML/DDL; a clean raw query is recorded at log level. It joins the shared
  detector list and the corpus harnesses.
- **Slow-upload defense (Phase 5).** The body read pass runs under
  `body_read_timeout_ms` (default 10 s); a trickling upload is refused with
  408. `max_body_size` is clamped to the 64 KiB replay limit with a warning.
- **Shadow-comparison report (Phase 6/8).** `tests/shadow_report.rs` runs a
  labeled corpus through the legacy engine and the pipeline (one shared
  detector list) and writes `docs/shadow-report.md`: **pipeline detects 21/21
  attacks with 0/12 benign false positives; legacy detects 16/21; pipeline
  stricter in 6 cases, weaker in 0.**
- **Coverage-guided fuzz targets (Phase 6).** `fuzz/` ships `detectors` and
  `canonicalizer` targets (cargo-fuzz, nightly). Smoke campaigns:
  detectors 34,660 runs / 30 s clean; canonicalizer 162,093 runs / 30 s clean.
  The canonicalizer campaign found one real convergence bound (a target that
  exhausts the decode budget decodes further on a second pass; stable from
  the second pass on) - locked in a unit test and documented in
  `docs/security-engine.md`.
- **Signal-quality fix.** A pipeline verdict at `Log` level now maps to
  `Pass` (it previously surfaced as `Monitor`), so weak lexical signals no
  longer create monitor events for benign traffic; `Monitor` semantics are
  unchanged.

## Known limitations (unchanged from v0.21.0)

- Body inspection is windowed at the head and, for larger bodies, continues
  through tail scanning; a payload placed arbitrarily deep is seen as its
  chunks arrive, but the upstream has already received the header and head
  when a tail payload aborts the connection (no clean 403 is possible
  mid-stream).
- WebSocket inspection covers the handshake and both frame directions;
  permessage-deflate (compressed frames) is not decompressed.
- OpenAPI validation covers operations, methods, required query parameters
  and JSON-body schemas; non-JSON bodies and remote `$ref`s are not resolved.
- Five CRS corpus expectations remain documented divergences.
