# VarmanWAF v1.1.7 - The clarity round: WAF model, site overview, and the new site

**Release date:** 2026-10-22 **Images:** `sovichetra/varmanwaf:1.1.7`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.1.7`

No engine, API or database changes: this round makes the existing behaviour
easier to understand and the surfaces faster to reach. It is a drop-in
upgrade with no migration.

## Why

An operator tested
`?id=1' union select user(),1,3--` against a live site, saw the origin's login
page, and concluded that nothing happened. The event was in fact recorded:

```
action monitor  rule sig.sqli.union_bare  path /  score 55
```

The site's **enforcement mode** was `monitor`, so nothing was blocked - and
the built-in SQLi gate starts at score 60 while the test scored 55. Three
surfaces (WAF rules, policy tuning, policies) all looked like "the WAF", and
the user guide still described the old Off / Detection / Prevention model.

## Documentation (the fix that matters most)

- `docs/user-guide.md` WAF section rewritten around the real model:
  - **WAF rules** detect and score.
  - **Policy tuning** decides what the site does with findings (Monitor /
    Block, paranoia, advanced mode, monitor-only categories, exclusions).
  - **Policies** are reusable tuning bundles that sites follow.
  - New checklist: **"I sent an attack and nothing was blocked"** - mode,
    event presence, score threshold, rule/paranoia gates, re-test.
- `docs/navigation-ia.md`: the site workspace is a 14-tab bar; documents the
  new Overview tab, the Open action and the clickable domain.
- `docs/ui-language.md`: dismissible notes (7-day key), fullscreen canvases,
  and the site overview.

## Console

- **Per-site Overview** (`/sites/:id/overview`) is now the site's default tab:
  24-hour requests / blocked / security events / unique IPs, the protection
  posture in force (mode, paranoia, body inspection, engine mode), the active
  certificate, origin health, and the latest findings with links into the
  owning surfaces. `/sites/:id` redirects here; old `origin` links still work.
- **Dismissible informational notes**: every page-level overview box has a
  close X and remembers the choice for seven days
  (`localStorage` key `varman.banner.<key>`). Live warnings deliberately stay.
- **Topology fullscreen**: the fleet and site graphs have Expand / Exit
  fullscreen, reflected on Escape and OS-level exits.
- **Sites list**: an explicit **Open** action on every row, and the domain
  itself links to the site overview; row click no longer jumps into origin.

## Website

The public site now follows the visual language the operator asked for
(GuardianWAF): navy `#0b1220` / light `#f5f8fd`, Space Grotesk for UI,
JetBrains Mono for code and labels, accent `#88c2ff`, a 1728px grid with
`clamp(20px, 3.5vw, 72px)` gutters and hairline borders. Content, copy,
screenshots and assets remain VarmanWAF's own - only the layout, palette and
typography were matched. Dark is the default; the light theme follows the
system preference and can be pinned with the nav toggle. The hero now shows
the real decision path for the SQLi probe that started this round.

## Upgrading

```bash
cd ~/varmanwaf && docker compose pull
docker compose up -d --force-recreate varman
```

No config or schema action is required. If the site should block instead of
record, set `Web Protection → Policy tuning → Enforcement mode` to **Block**
and re-test; the event list will then show `action: block`.
