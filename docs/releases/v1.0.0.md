# VarmanWAF v1.0.0 - The first official release

**Release date:** 2026-10-16 **Images:** `sovichetra/varmanwaf:1.0.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v1.0.0`

The program reaches its first official release. Everything shipped across
the 0.39-0.64 rounds is in one verified build: the native Varman engine
enforcing, the full operator surface (policy tuning, access control with
ipverse data, API assets with bounded learning and per-operation controls,
exclusion packages with upstream SecLang imports, alerts, reports, fleet),
and a documentation set that includes a complete Khmer user guide with
screenshots of every feature.

## What this round brings

- **README refreshed for the release** - the engine section now states the
  truth (the native engine enforces; `varman` / `legacy` / `shadow` per
  site), plus a feature-by-feature console table and the release workflow
  (local gate, full sweep, version-bump rule).
- **`docs/features.md`** - the complete feature inventory: every console
  surface, how it works, the API module behind it, and the honest limits
  (what a surface deliberately does *not* do).
- **`build-artifacts/run-e2e-all.ps1`** - the full regression sweep: all 40
  feature E2E scripts against the deployed stack, paced for the login
  limiter (10 attempts / 60s / IP - the limiter is part of the product), with
  a pass/fail summary and a non-zero exit on any failure.
- **`docs/user-guide-km/index.html`** - the full Khmer user guide: every
  feature in step-by-step detail with screenshots captured from this build.
- **`docs/benchmarks/v1.0.0.md`** - the performance benchmark report:
  data-plane pass-through throughput and latency at several concurrencies,
  WAF block verdict latency (engine path), the auto-block refusal lane, and
  control-plane API latency.
- **Benchmark and screenshot tooling** - `build-artifacts/bench.js` +
  `run-benchmark.ps1` (keep-alive load generator with percentile reporting)
  and `build-artifacts/screenshots/capture.js` (puppeteer-core against the
  installed browser, session seeded from one API login).
