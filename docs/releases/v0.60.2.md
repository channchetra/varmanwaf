# VarmanWAF v0.60.2 - Import report accuracy (continuation lines)

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.60.2`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.60.2`

The second live-gate catch from the import round: the import itself worked
(the WordPress plugin stored, attached, pushed, served), but the **report
counted physical lines**, and the CRS plugins split one rule across many
`\`-continued lines - so a file with 554 inline exclusion controls was
reported as having **one**. A misleading report is the one thing this
program does not ship. 0.60.0/0.60.1 images were never published.

## What this round changes

- **Logical-line scanning**: the report joins `\` continuations first (the
  shape the SecLang parser itself reads), then classifies. The WordPress
  plugin now reports its true shape: ~136 rules, ~554 inline exclusion
  controls, the addressed CRS rule ids, and the version from its comment.
- **A test pins the continuation case**: one logical directive split across
  three physical lines reports one rule, one control, and the addressed id.
- The E2E expectations now assert the true magnitudes (rules > 100,
  controls > 100).

## Verification at release

- `cargo fmt --check` exit 0; control tests **378**; engine **496**; plugin
  **200**; agent **42**; clippy `-D warnings` clean; web unchanged.
- Live E2E (import script, re-run on this build): the real WordPress plugin
  imports with a truthful report; a non-root attach is refused (`400`);
  attaching at `/` pushes the bundle and the site keeps serving with no
  compile failure; the binding and package are removed.
