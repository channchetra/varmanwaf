# VarmanWAF v0.49.0 - Site navigation: the orphaned Settings page surfaced, tab bar grouped

**Release date:** 2026-10-15 **Images:** `sovichetra/varmanwaf:0.49.0`,
`sovichetra/varmanwaf:latest` **Tag:** `v0.49.0`

Continuing the navigation study at the site level (recorded in
[`docs/navigation-ia.md`](../navigation-ia.md#site-level-v0490)). Most of
the site surface was already consolidated in earlier rounds - Web
Protection is a tabbed hub (engine, rules, policy, CC), Access control
covers IP rules + geo, and every legacy path redirects into them - but the
study found two real problems.

## What this round brings

- **The site Settings page was orphaned.** The disconnected-edge failover
  policy (`/sites/:id/settings`) was routed but linked from nowhere - a
  shipped feature invisible in the UI. It is now a tab in the site bar and
  an entry in the sidebar's "This site" group.
- **The tab bar and the sidebar's "This site" group disagreed** (rewrite
  rules missing from the sidebar, settings missing from both). They now
  list the same nine destinations.
- **The site tab bar is grouped by scope** with subtle separators:
  `Origin | Protection · Rate limiting · Bot · Access | Caching · SSL/TLS ·
  Traffic | Rewrite · Settings` - the bar reads as sections instead of a
  flat list.

## Verification at release

- `npx tsc -b`, `npx vite build` and eslint clean; 20/20 web unit tests;
  bundle markers for the surfaced surfaces.
- Live E2E (site-tabs script): version and health; the formerly orphaned
  `/sites/{id}/settings` route serves the console; the failover API behind
  it answers (`policy` + resolved `default_fail_open`); the control-plane
  smoke unchanged.
- No Rust edits: the server is byte-identical to v0.48.0.
