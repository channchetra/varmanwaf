# VarmanWAF v0.28.0 - Policy & Rule Control Plane, round 5 (P5: templates & recipes)

**Release date:** 2026-10-13 • **Images:** `sovichetra/varmanwaf:0.28.0`,
`sovichetra/varmanwaf:latest` • **Tag:** `v0.28.0`

Round P5 of the Tiyi-informed control model: **starter content**. New
policies begin from a reviewed template instead of a blank page, and common
rules are added through parameterized recipes that render into the rule
expression language.

## What this round brings

- **Built-in policy templates** (our layer format, compiled in and
  reviewed): `observe` (monitor at PL2 — the safe starting point),
  `standard` (block at PL1), `strict` (block at PL2 + deep body
  inspection) and `extra-strict` (block at PL3 + deep body inspection).
  `GET /api/v1/policies/templates` lists them with parsed layers;
  `POST /api/v1/policies/from-template` creates a policy from one. Every
  template payload goes through the same layer validation as an API write
  — a test fails the build if a template stops compiling.
- **Rule recipes**: `block-path`, `challenge-path`, `block-query-param`
  and `block-user-agent`. `GET /api/v1/policies/recipes` lists them with
  their parameters; `POST /api/v1/policies/{id}/recipes` renders the rule,
  merges it into the policy's `custom_rules` layer (replacing a rule with
  the same name, so re-applying updates instead of duplicating), records a
  version and pushes the change to assigned sites.
- **Parameter safety**: path parameters must start with `/` and carry no
  quotes, backslashes, whitespace or control bytes; token/parameter names
  are restricted to letters, digits and `-_.:`. The rendered rule is then
  validated with the same schema as any layer write, so a recipe can never
  inject an expression fragment.
- **Dashboard**: the create dialog gains a template picker (with the
  template's description), and the Custom rules tab gains an **Add from
  recipe** gallery that renders a parameter form per recipe.

## Verification at release

- `cargo test --workspace` green with new coverage: every template layer
  passes `validate_layer`; every recipe renders a valid rule with sample
  parameters; parameter validation rejects missing values, relative paths
  and injection attempts (`"/x\" or true or \""`); unknown recipes are
  named in the error. Control-plane suite at 323 tests; clippy
  `-D warnings` clean; `tsc -b && vite build` clean.
- Live E2E: a policy created from the `standard` template (blocking at
  PL1) answered the attack probe with **403**; applying the `block-path`
  recipe for `/recipe-block` produced **403** on that path while benign
  traffic stayed **200**; a recipe re-apply updated rather than
  duplicated; the recipe's parameters were rejected with 400 when the path
  did not start with `/`.
